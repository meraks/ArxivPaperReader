## 第 1 章 概述

### 1.1 一句话定位

本文提出一套面向国际信息学奥林匹克（IOI）与 ICPC 等竞技编程竞赛的端到端模型专用化管线（大规模题目筛选 + 合成推理轨迹 + 长上下文 SFT + 可执行奖励 RL + 迭代测试时修正 GenCorrect），训练出的 Nemotron-3-Ultra-CC 系统在 IOI 2026 题目集的前瞻性（live）评测中以 535.4/600 超过金牌线（361.12）与最高分人类选手（498.27），成为首个在 IOI 题目集上超过最高分人类的 AI 系统。

### 1.2 核心贡献

1. **端到端竞技编程专用化管线**：从 16 个区域/国际竞赛家族及在线平台筛选 22,000 道题并包装成可执行评测环境，用 DeepSeek-V4-Flash 生成 120 万（Nano）与 477,642（Ultra）条合成推理轨迹，结合最长 262K token 的长上下文 SFT 与可执行奖励 RL。
2. **GenCorrect 测试时计算策略**：在每题最多 50 次提交的硬约束下，通过最多 5 轮「并行生成 200 候选 → 评分盲聚类取 10 代表 → 提交执行 → 子任务级反馈累积」闭环，将并行采样能力浓缩为逐轮修正。
3. **系统性的组件归因分析**：隔离 synthetic data、SFT、RL、模型规模与测试时计算各自对竞技编程性能的贡献（含每组件消融与检查点初始化实验），而非仅报告端到端结果。
4. **IOI 2026 前瞻性评测**：在人类同等的时限、禁网、提交约束下，live 得 535.4/600，超过金牌线 174.3 分、超过最高分人类 37.1 分；据作者称这是首次有 AI 系统在 IOI 题目集上超过最高分人类（该运行为非官方、非监督基准，未计入官方排名）。

### 1.3 关键结果速览

- **IOI 2026（live，Competition Ultra-CC）**：535.40/600，金牌线 361.12，最高分人类 498.27（+174.3 分/+37.1 分）。赛后用通用五轮 GenCorrect 管线复跑均值 521.72（范围 495.0–545.8），live 结果高出复跑均值 13.68 分。
- **Nemotron-3-Ultra-CC（550B-A55B，仅 SFT 无 RL）**：IOI 2025 Score@1 从 45.5% 升至 50.7%，五轮 GenCorrect 后达 502.0/600（超 2025 金牌线 438.3，第 3 轮即越过）；ICPC 2025 Pass@1 54.0%→57.4%；LCB Pro Pass@1 72.6%→74.5%。
- **Nemotron-3-Nano-CC（30B-A3B，SFT + RL）**：IOI 2025 Score@1 从 130（21.7%）经 SFT 至约 280（46.7%）、RL 后 291（48.5%），五轮 GenCorrect 后 468.2 超 2025 金牌线；ICPC 2025 Pass@1 16.9%→51.0%；LCB Pro Pass@1 17.6%→71.6%（超过 gpt-oss-120b、Qwen3.6-35B-A3B、Nemotron-Cascade-2-30B-A3B 与 DeepSeek-V4-Flash）。
- **组件贡献排序**：单样本增益主要来自 SFT（第一 epoch 收益最大，第三 epoch 趋于饱和）；RL 仅带来小幅增量（IOI +1.8pp、ICPC +3.7pp、LCB +0.9pp）；GenCorrect 的迭代修正大幅放大优势（Nano +107.6 分、Ultra +158.1 分），且强基座模型的优势随测试时计算而扩大。
- **训练数据规模效应反直觉点**：仅 1 epoch / 477,642 样本的 Ultra-CC（SFT-only）在三个基准上全面超过 3 epochs×120 万样本 + RL 的 Nano-CC——规模允许时，用少量 SFT 适配强基座优于对弱基座做大量后训练。

## 第 2 章 竞赛设置与评测协议

本章交代论文全部实验所依附的竞赛规则、评测基准、指标定义、采样平均口径与防污染设计。

这些设置并非背景性铺垫。IOI 与 ICPC 在评分反馈粒度上的结构性差异，直接决定了 GenCorrect 闭环在不同赛制下可利用的信息量，是后文行为差异分析的根基；采样平均口径、统一复测政策与防污染设计，则共同保证了各模型间对比的可信度。

论文的评测集覆盖 IOI 2025、ICPC 2025 与 LiveCodeBench Pro（LCB Pro），以下各节依次展开。

### 2.1 IOI 竞赛规则

国际信息学奥林匹克（International Olympiad in Informatics， IOI）面向中学生，是论文 live 评测所对齐的赛制之一。IOI 2025 的核心规则可概括如下。

- 比赛在两个比赛日进行，共设 6 道题目。
- 每题满分 100 分，评测按 subtask 部分给分：题目被划分为若干 subtask，某个 subtask 内的全部测试用例通过即可获得该 subtask 对应的分数。
- 每题最多提交 50 次，选手可在提交预算内反复尝试不同思路与实现。
- 总分为各题得分之和，每题满分 100 分、共 6 题，故总分上限为 600 分。

subtask 机制是理解 IOI 评分的钥匙：题目通常按输入规模或约束强度分档，低档位用朴素解法即可通过，高档位需要更优的算法。

解法不必在全部用例上正确也能取得部分分，评测对"接近正确"的解法是平滑的——次优算法换得的分数与其覆盖范围相称，努力不会被整体归零。

反馈因此是 subtask 级的：每次提交返回的不是单一的对错判定，而是各 subtask 的通过情况与得分。一次提交即可暴露解法的覆盖边界——哪些档位已经通过、哪些尚未通过。

选手与模型都能据此定位薄弱环节，把后续的提交定向投向未覆盖的 subtask。

提交预算与部分分反馈配合，构成"提交—反馈—改进"的循环空间；后文 GenCorrect 对每题提交机会的分配，正运行在这一预算之内。

对模型评测而言，IOI 协议下的得分因此是连续量：完全解出、部分覆盖与完全失败构成清晰的状态层次，进步可以被细粒度地度量，而非被二值化地抹平。

奖牌不设固定分数线，而是按选手分数的最终分布划定比例：金牌约对应前 1/12，银牌约对应前 1/6，铜牌约对应前 1/4。

| 奖牌 | 比例口径 |
| --- | --- |
| 金牌 | 约 前 1/12 |
| 银牌 | 约 前 1/6 |
| 铜牌 | 约 前 1/4 |

按比例而非按固定分数线划线，意味着奖牌归属取决于当届选手的整体分布。

评估离线成绩时，论文同时报告原始分（600 分制）与归一化百分比，并以当届官方奖牌线（如 IOI 2025 金牌线 438.3、IOI 2026 金牌线 361.12）为参照判断是否达到金牌水平；奖牌线本身由当届分数分布划定，并非固定阈值。

上述要素——部分分、提交预算与比例奖牌——共同定义了论文在 IOI 侧的全部评测语义。

### 2.2 ICPC 竞赛规则

国际大学生程序设计竞赛（International Collegiate Programming Contest， ICPC）2025 世界总决赛在组织形式与评分规则上与 IOI 形成鲜明对照，其规则要点如下。

- 每队 3 人，共用一台机器协作解题，比赛时长 5 小时。
- 共 12 道题目，难度谱系从签到题到压轴题连续分布。
- 评分为二进制判定：只有当某题的全部隐藏用例都通过时，该题才算被解出；不存在任何形式的部分分。
- 排名首先按解出题数，同题数下按罚时（time penalty）排序；罚时等于解出该题之前的比赛用时，加上该题每次错误提交累加的 20 分钟。

| 维度 | ICPC 2025 世界总决赛规则 |
| --- | --- |
| 队伍与机器 | 3 人共用一机 |
| 时长 | 5 小时 |
| 题量 | 12 题 |
| 判定 | 二进制，全部隐藏用例通过才算解出 |
| 罚时 | 通过前用时 + 每次错误提交 20 分钟 |
| 奖牌 | 前 4 名金、第 5-8 名银、第 9-12 名铜 |

共用一台机器使机器时间成为稀缺资源：调试、编译与提交须在队内协调排队，人手与算力的配比本身就是策略变量。这与 IOI 选手各自独立作答的形态截然不同。

罚时规则对策略有实质性约束：错误提交不仅消耗机器时间，还会直接累加进最终成绩，盲目试错的代价远高于 IOI。

解题顺序与提交谨慎性因此都进入成绩的构成：早解出降低用时项，少错提交降低罚项，策略与实力共同决定名次。

二进制判定的反馈信息量极低：隐藏用例不公开，每次提交只告知通过与不通过，不暴露通过了多少用例、错在何处。

选手（以及模型）无法从失败的提交中读出解法距离正确有多近，只能依靠重新调试或构造全新假设。

对模型评测而言，ICPC 协议把注意力完全压在"完整正确"上：成绩是解出题数与罚时的函数，部分覆盖没有任何价值，次优解与错误解在记分上同样归零。

奖牌按名次划定：前 4 名金牌、第 5-8 名银牌、第 9-12 名铜牌。与 IOI 的比例口径相比，ICPC 的奖牌完全由排名位置决定，名次竞争的排他性更强。

反馈粒度与奖牌规则上的差异并非细节，而是制度性的：任何依赖评测反馈做迭代改进的方法，可用的信号从 subtask 级分数退化为通过与否的对错判定，修正空间的上限随之改变。

这是后文 GenCorrect 行为差异的制度根源，也是贯穿全文评测叙事的主线；后文关于 GenCorrect 的设计与实验分析，正是在这套规则语义上展开的。

### 2.3 评测基准与指标

论文的评测集为 IOI 2025、ICPC 2025 与 LiveCodeBench Pro（LCB Pro）：IOI 2025 与 ICPC 2025 采用真实竞赛的完整题目与官方评分协议，LCB Pro 作为补充基准参与模型间的横向对比。

指标体系围绕竞赛评分协议定义，核心是 Pass@1 与 Score@k。

**Pass@1** 衡量一次采样下的解出比例。在 ICPC 语境下，Pass@1 指 12 道题中被解出的题目比例；这一口径与二进制判定保持一致——题目只有解出与未解出之分。

**Score@k** 的计算流程是：将生成的解划分为若干独立的 run；在每个 run 组内，对每道题的各个 subtask 跨样本保留最高得分并求和；再对所有 runs 取平均。

该定义包含双层结构：组内对每题做 subtask 级择优求和，组间对 runs 取平均。Score@1 即单样本得分，Score@200 即并行 200 次采样的择优得分。

| 指标 | 定义 |
| --- | --- |
| Pass@1 | 一次采样解出比例；ICPC 口径为 12 题中的解出比例 |
| Score@k | 独立 run 组内每题各 subtask 保留最高分并求和，再对 runs 取平均 |
| Score@1 | 单样本 |
| Score@200 | 并行 200 采样 |

可以把每个 run 理解为一次独立的"参赛记录"：组内择优相当于从多条记录中为每道题拼出各 subtask 的最好成绩，再对多次这样的拼取平均。

Score@k 因此度量的是并行采样与择优组合下的口径，而非单次参赛的期望表现。独立性意味着组内样本共享同一题面与判分标准，但生成过程互不依赖；择优发生在判分之后，不占用任何提交预算，这与真实选手受提交次数约束的处境并不相同。

Pass@1 与 Score@k 构成从单样本口径到系统口径的谱系，论文在两者之间切换报告时始终保持口径显式，避免读者把单样本能力与并行采样能力混为一谈。

Score@k 与 subtask 结构的耦合值得强调：跨样本在 subtask 级别择优，只有在存在部分分制度的 IOI 式评分下才有意义——多个各覆盖不同 subtask 的次优解，可以聚合出高于任何单样本的分数。

在 ICPC 的二进制判定下，同题择优退化为"任一样本完全通过"，subtask 级的聚合无从发生。该指标家族在不同赛制下实际度量的能力并不相同：Score@200 在 IOI 下度量互补解的聚合空间，在 ICPC 下度量单样本完整命中的概率。

反馈信息量的差异同样是后文 GenCorrect 行为差异的铺垫。GenCorrect 以评测反馈作为迭代修正的依据：在 IOI 的 subtask 部分分反馈下，系统可以定位薄弱 subtask 并针对性改进；在 ICPC 的二进制反馈下，反馈只携带通过与不通过的信息，修正只能依靠生成侧的多样性探索。

后文对 GenCorrect 行为差异的全部分析，均以本节所述的制度差异为根源；阅读后续章节时应始终对照——反馈通道的丰富程度，决定了闭环修正能够走多远。

真实竞赛协议与标准化基准互为补充，覆盖了模型能力光谱的不同侧面，指标的赛制依赖性则提醒读者：跨基准的数字对比须连同各自口径一并解读。

### 2.4 采样与平均口径

竞赛题目数量有限，单次评测的随机方差不可忽略；采样随机性、题目顺序与判分边界都会引入波动。论文为所有报告数字规定了明确的平均口径。

| 结果类型 | 平均 runs |
| --- | --- |
| 最终 IOI/ICPC 结果 | 1,000 |
| 中间检查点 | 50 |
| Score@200 | 5 |
| LCB Pro | 8 |

口径的分档有其逻辑：训练过程中的中间检查点只需分辨趋势，较稀疏的平均即可。

最终 IOI/ICPC 结论承担奖牌线判断，须以最密的平均压低方差；Score@200 的每个样本本身已含 200 次采样的择优，外层平均可以相应放松。

LCB Pro 按其基准规模取适中档位。

不同口径下的数字不可直接互换比较：中间检查点曲线与最终结果之间、Score@200 与 Pass@1 之间，口径不同，差距的含义也不同。

与平均口径配套的是统一复测政策：所有对比结果一律使用作者自建的评测 harness 复测，不引用他人报告数值。

不同来源的评测实现在隐藏用例集合、时间与内存限制、判分严格度上存在差异，直接采信外部报告数值会使模型间对比失去可比性。

统一复测把全部对比置于同一评测管线之下，数字之间的差异才可归因于模型本身，而非评测实现。后文如无特别说明，报告数字均遵循本节口径。

### 2.5 防污染设计

数据污染是竞技编程评测的核心威胁：竞赛题目在社区中流传广泛，无论原题还是改写变体，混入训练语料都会令评测成绩失去意义。论文对此采取层层设防的策略。

首先是语料排除。SFT 与 RL 的训练语料均排除 IOI 2025、ICPC 2025 与 LCB Pro 的全部题目，并执行去重，以进一步剔除语义相近的变体题目。

去重覆盖的正是"换皮题"这类最隐蔽的污染形态——题面重述、变量改名或约束微调后的同源题。

其次是前瞻评测。IOI 2026 作为严格前瞻评测，在题目公开之前已完成运行：评测时间点先于题目公开，从时间线上杜绝了任何泄漏的可能。

语料排除针对的是已知评测集，前瞻评测针对的是训练数据之后新出现的题目，合起来覆盖了污染的主要通道——前者堵住"见过原题"，后者堵住"事后混入"。

防污染与前瞻评测的分工还有更深的意义：前者保证对比的公平，后者保证结果的时效可信——模型面对的是从未见过的最新题目，与人类选手同题同卷，成绩反映的是泛化而非记忆。

将本节与第 2.4 节的复测政策合观，实验可信度的保障是完整的：防污染设计排除数据层面的捷径，统一评测管线排除评测层面的偏差，大规模平均排除采样层面的随机性。后文所有结论都建立在这道基线之上。

## 第 3 章 数据与后训练管线

### 3.1 题目筛选与可执行评测环境

整体管线如图 Figure 2 所示。作者从 16 个横跨近二十年的区域/国际竞赛家族以及在线编程平台收集 **22,000 道题**。每条自动化（agentic）管线按「竞赛-年份」对抓取题面、时间/内存限制、官方测试用例、辅助文件与参考解，打包成统一的可执行评测环境。

环境经过两级验证：已知正确的解必须得到预期分数、已知错误的解必须失败；此外用 gpt-oss-120b 生成候选解并编译执行，用于暴露题面错误、缺失辅助文件、编译器不兼容与测试 harness 不一致等问题。判定为不一致（参考解失败、提供解无法编译、结果不稳定）的环境会被剔除。

防污染是硬约束：IOI 2025、ICPC 2025 与 LiveCodeBench Pro 的全部题目从 SFT 与 RL 语料中排除，并对剩余训练题与该三个评测集做去重；IOI 2026 无需回溯式过滤——系统在题目公开前即完成运行，属严格前瞻评测。

RL 语料额外要求评测顺序执行耗时 ≤300 秒：从 4,000 道可靠题中筛出 **3,219 道**，按父题目级切分为 2,847 道训练 + 372 道验证（同一道题的 subtask 不会跨集合），验证题尽量覆盖每个竞赛-年份对。

### 3.2 合成推理轨迹生成

SFT 数据全部由 **DeepSeek-V4-Flash** 作为 teacher 生成：为 Nemotron-3-Nano-30B-A3B 生成 **120 万条**推理轨迹，为 Nemotron-3-Ultra-550B-A55B 生成 **477,642 条**。

- **按难度分配生成预算**：题目分为 easy / medium / hard，越难的题分配越多的生成次数（Figure 3）。
- **自改进轨迹（self-improvement traces）**：teacher 拿到「题目 + 先前生成的某个解」后被要求产出改进后的解。这类样本把 GenCorrect 在推理时的迭代修正行为提前暴露给学生模型。

### 3.3 监督微调（SFT）

Nano-CC 训 3 个 epoch、Ultra-CC 训 1 个 epoch，均使用全局 batch size 64、序列打包最长 **262K token**（长题面 + 长推理轨迹）。Ultra 从它的 **RLVR-teacher 检查点**（此前用于把强推理能力蒸馏进通用模型的阶段产物）初始化，而非从预训练基座开始。完整配置见论文 Table 5（下表为原表转写）。

## 第 4 章 GenCorrect：受提交预算约束的测试时计算

### 4.1 动机与总体设计

Score@200 这类并行采样指标能衡量「池子里有好解」的概率，但真实竞赛要求把答案浓缩进有限次提交。IOI 每题最多 50 次提交——GenCorrect 把这个预算切成 **5 轮 × 每轮 10 次提交**，每轮先并行生成最多 200 个候选，执行评测后把子任务级反馈带进下一轮，形成闭环修正（Figure 4）。相比此前把题目手工拆成子任务再分别求解的做法（OpenAI o1-ioi、GenCluster 等），GenCorrect 把完整题目（含全部 subtask）交给模型，由模型自己决定先攻哪个子任务，因此每道题所需的生成次数更少。

每轮由四步组成：**生成 → 多样性选择 → 执行 → 细化**。ICPC（二进制反馈）场景下，循环持续到题目解出或性能平台期为止。

### 4.2 生成与多样性选择（评分盲聚类）

每轮生成最多 200 个并行候选解并本地编译（测试时提示词指定 C++20，见论文附录 C.1；RL rollout 阶段则为 C++17），第一轮只给题面，后续轮次额外携带前序的解与评测反馈。

过滤掉无效输出后，用**与分数无关**的局部启发式 $Q(c)$ 初始化中心集，再迭代选取离现有中心最远的候选：

$$c_{\mathrm{next}} \in \arg\max_{c \notin C} \min_{z \in C}\left[1-\operatorname{sim}(c,z)\right] \tag{1}$$

其中 $\operatorname{sim}(c,z)$ 是归一化代码的 token shingle 相似度。取 $K=10$ 个中心后，把其余候选分配给最相似的中心，每个簇内取 $Q(c)$ 最高的候选作为代表提交——簇成员关系保证多样性，$Q(c)$ 保证代表是「结构上最完整」的那个。

过滤规则（可渐进放宽）：候选必须能编译、归一化代码非空且 ≥40 token、结构特征分非负。$Q(c)$ 的完整定义为：

$$Q(c)=\left(\operatorname{Compiles}(c),\operatorname{FeatureScore}(c),\left\lfloor \operatorname{CodeLength}(c)/800 \right\rfloor,\operatorname{ExactFrequency}(c),\operatorname{CodeLength}(c),-\operatorname{GeneratedTokens}(c),-\operatorname{RunId}(c)\right) \tag{3}$$

按字典序比较、取大者。FeatureScore 奖励完整 C++ 程序的特征（头文件、main 函数、输入输出、return 语句），惩罚未完成占位；$\operatorname{ExactFrequency}(c)$ 是归一化代码完全相同的候选数量，$\operatorname{GeneratedTokens}(c)$ 是原始模型输出长度，$\operatorname{RunId}(c)$ 是确定性生成序号。**关键性质：$Q(c)$ 与聚类全程不使用竞赛分数**——所有筛选、聚类与代表选择都在本轮评测反馈可见之前完成。

### 4.3 执行与子任务反馈累积

10 个代表提交给评测器。IOI 的反馈是每个子任务的得分；把每个子任务迄今见过的最高分累积为内部反馈状态：

$$A_r(t) = \max\left(A_{r-1}(t),\; \max_{c \in S_r} s_t(c)\right), \qquad A_0(t) = 0 \tag{2}$$

$S_r$ 是第 $r$ 轮提交的解，$s_t(c)$ 是解 $c$ 在子任务 $t$ 上的得分。$A_r(t)$ 只用于引导后续生成，不改变评测器的官方计分。

### 4.4 细化与参考传递

每轮结束后，该轮总分最高的提交成为**主解**（平分时用评分盲启发式裁决），再从「当前轮提交 + 前几轮保留的解」中挑 3 个互补参考：①全局最强候选；②针对最大剩余子任务缺口（largest remaining subtask gap）的候选；③对剩余缺口整体覆盖最好的候选。缺口由累积反馈状态 $A_r$ 决定，相似度与 $Q(c)$ 作为去重与偏好局部完整程序的 tie-breaker。

下一轮的生成条件化为：题面 + 累积子任务反馈向量 $A_r$ + 主解 + 3 个参考解。这样既保住已拿下的子任务，又定向攻击剩余缺口，同时靠参考多样性防止坍缩到单一路径。

### 4.5 与并行采样的本质差别

Score@200 是「生成 200 个解、从 200 个里取最好」——一次性、无反馈。GenCorrect 则是「200 个生成浓缩成 10 次提交、评测反馈回来指导下一轮再生成 200 个」，把同一笔生成预算沿时间轴复用。论文 4.5 节的数据显示这条反馈通路价值显著：Nano-CC 从第 1 轮到第 5 轮的平均得分上升 107.6 分，远超任何并行采样带来的收益（详见第 5.5 节）。

## 第 5 章 实验结果与消融

### 5.1 评测设置

评测集为 **IOI 2025、ICPC 2025 与 LiveCodeBench Pro（LCB Pro）**，三者题目全部从 SFT/RL 语料中排除并去重。指标：

- **Score@k**：把生成解分组成独立 run，组内每道题的各子任务取最高分、跨子任务求和、跨题求和，再对 runs 取平均。Score@1 反映单样本能力，Score@200 反映并行采样上限。
- **Pass@1**：单次采样解出问题的比例；ICPC Pass@1 表示 12 题中的解出比例。

平均口径：最终 IOI/ICPC 结果平均 1,000 runs、中间检查点 50 runs、Score@200 平均 5 runs、LCB Pro 平均 8 runs。**所有对比模型的竞赛结果均由作者用自家评测 harness 重新测得**（而非抄录对应模型报告），这是与许多「引用式」对比的关键区别。

对比基线：gpt-oss-120b、Qwen3.6-35B-A3B、Nemotron-Cascade-2-30B-A3B、Nemotron-3-Nano/Ultra 基座、DeepSeek-V4-Flash 与 DeepSeek-V4-Pro（Max thinking）、GLM-5.2。

### 5.2 主结果

论文 Table 1 收录全部 10 个模型在三个基准上的结果（下表为原表转写，IOI 列已由原文归一化为百分比；原始满分 600）：

| Model | IOI 2025 Score@1 | ICPC 2025 Pass@1 | LCB Pro Pass@1 |
|:---|:---:|:---:|:---:|
| Nemotron-3-Nano-30B-A3B | 21.7% | 16.9% | 17.6% |
| Nemotron-Cascade-2-30B-A3B | 37.2% | 42.0% | 45.6% |
| gpt-oss-120b | 40.7% | 45.8% | 66.4% |
| Qwen3.6-35B-A3B | 40.8% | 32.0% | 58.4% |
| Nemotron-3-Ultra-550B-A55B | 45.5% | 54.0% | 72.6% |
| DeepSeek-V4-Flash | 55.3% | 65.8% | 69.5% |
| DeepSeek-V4-Pro | 56.8% | 69.6% | 78.2% |
| GLM-5.2 | 66.0% | 65.7% | 83.8% |
| **Nemotron-3-Nano-CC** | **48.5%** | **51.0%** | **71.6%** |
| **Nemotron-3-Ultra-CC** | **50.7%** | **57.4%** | **74.5%** |

要点解读：

- **Nano-CC 以小胜大**：仅 3B 激活参数，IOI 2025 Score@1 从基座的 21.7% 提到 48.5%（原始分 130→291），Score@200 从 272 提到 461，**同时超过基座 Nemotron-3-Ultra-550B-A55B（45.5%）**。在同激活参数规模档（≤3B active）内，Nano-CC 是评测中最强的模型。
- **天花板仍在大模型手里**：Score@1 上 Nano-CC 输给 DeepSeek-V4-Flash（55.3%）、DeepSeek-V4-Pro（56.8%）与 GLM-5.2（66.0%）三员大将；但在 LCB Pro 上 Nano-CC（71.6%）反超 DeepSeek-V4-Flash（69.5%）与 gpt-oss-120b（66.4%）、Qwen3.6-35B-A3B（58.4%）、Nemotron-Cascade-2-30B-A3B（45.6%）。
- **Ultra-CC 全榜最高**：仅 SFT（1 epoch）就把它推到 50.7% / 57.4% / 74.5%，分别比 Nano-CC 高 2.2 / 6.4 / 2.9 个百分点——尽管 Ultra-CC 没有 RL 且 SFT 数据量小得多。
- **IOI 与 LCB Pro 的排序并不完全一致**：如 DeepSeek-V4-Flash 在 IOI（55.3%）高居前列却在 LCB Pro（69.5%）低于 Nano-CC——IOI 的子任务部分分机制与 LCB Pro 的全有全无判定考察的能力略有差异。

### 5.3 SFT 的贡献：主要增益来源

Figure 6 与 §4.3 的消融显示 **SFT 贡献了 Nano-CC 单样本增益的绝大部分**：

- Nano 三 epoch：IOI 2025 Score@1 从 21.7% 升至约 46.7%（= 280/600 分，与论文引言及 §4.4 一致；论文 §4.3 该处另写 47.3%，与引言/§4.4 存在 0.6pp 出入，本报告采用与原始分 280 对应的 46.7%）；ICPC Pass@1 从 16.9% 升至 47.3%；LCB Pro Pass@1 从 17.6% 升至 70.7%（+53.1pp）。增益集中在前两个 epoch，第三 epoch 明显饱和。
- ⚠️ 原文章节间的一致性说明：论文 §4.3 与 §4.4 对「第 3 个 SFT epoch 检查点」的 IOI/ICPC 数值存在互换（§4.3 写作 IOI 47.3% / ICPC 46.7%，§4.4 写作 IOI 46.7% / ICPC 47.3%），且 §4.3 声称的 IOI SFT 增量 24.8pp 与任一端点（47.3−21.7=25.6pp 或 46.7−21.7=25.0pp）都不吻合。本报告统一采用与引言原始分 280（=46.7%，IOI）一致的一组端点：IOI 46.7%、ICPC 47.3%、LCB Pro 70.7%。
- Ultra 单 epoch（477,642 样本）：IOI 45.5%→50.7%，ICPC 54.0%→57.4%，LCB Pro 72.6%→74.5%——绝对增益（+5.2 / +3.4 / +1.9pp）远小于 Nano 的 SFT 增益，反映 Ultra 基座本身已经很强。
- **关键对照**：SFT-only 的 Ultra-CC 在三个基准上全面超过「3 epochs×120 万样本 + RL」的最终 Nano-CC。作者的结论：当模型规模与推理成本不是主要约束时，**用有限 SFT 适配更强的基座，优于对较弱基座做大量的后训练**。

### 5.4 RL 的贡献：稳定但有限的小幅增益

RL（GRPO）从第 3 个 SFT epoch 检查点出发（Figure 7(a)，§4.4）：

| 基准 | SFT 后（ep3） | + RL（step 39） | 增量 |
|:---|:---:|:---:|:---:|
| IOI 2025 Score@1 | 46.7% | 48.5% | +1.8pp |
| ICPC 2025 Pass@1 | 47.3% | 51.0% | +3.7pp |
| LCB Pro Pass@1 | 70.7% | 71.6% | +0.9pp |

增益在三个基准上都为正但幅度有限。作者给出两个机制性解释：①二进制奖励的 GRPO 中，只有当某题的 rollout 组内同时存在成功与失败样本时才产生相对学习信号，因此 RL 主要打磨模型能力前沿附近的题；②rollout 最长 255K token 却只收到一个终端执行奖励，稀疏的长程信用分配限制了增益幅度与稳定性。

初始化消融（Figure 7(b)，30 步后 IOI 2025 Score@1）回答了「RL 能否替代 SFT」：

- 从 base 直接 RL：21.7% → 24.9%（+3.2pp）——可执行奖励 RL 单独也能带来可测增益；
- 从 SFT epoch 1 / 2 / 3 检查点出发：43.0% / 47.1% / 48.7%。

结论：在本文训练预算下 RL 无法补回 SFT 提供的绝大部分能力（teacher 太强是主因），最佳路径是先 SFT 再 RL——最终模型（step 39，48.5%）从第 3 epoch SFT 检查点出发。

### 5.5 测试时计算的贡献：并行采样之外还有反馈通路

Score@200 与 GenCorrect 的对比拆开了「并行采样」与「带反馈的迭代修正」两种测试时扩展：

- **Score@200 上限**：Nano-CC 461 分 vs Ultra-CC 505 分（差距 44 分）——而两者 Score@1 仅差约 13 原始分（48.5% vs 50.7%）。并行采样先放大一次规模优势。
- **GenCorrect 轮次曲线**（Figure 8(a)，均值）：Nano-CC 第 1 轮 360.6 → 第 5 轮 468.2（+107.6 分）；Ultra-CC 第 1 轮 343.9 → 第 5 轮 502.0（+158.1 分）。Ultra-CC 第 1 轮低于 Nano-CC，但每轮修正收益更大，最终领先 33.8 分。
- **过线节奏**：Ultra-CC 第 3 轮越过 IOI 2025 金牌线（438.3），Nano-CC 第 4 轮才越过——修正效率与基座能力正相关。
- **ICPC 二进制反馈平台期**（Figure 8(b)）：Nano-CC 解出题数 8.6→9.4（第 2 轮达 9 题、第 3 轮平台期——9 题恰好等于第 4 名金牌队的成绩）；Ultra-CC 9.0→9.6（第 2 轮即达 9 题并保持）。两个模型都比 IOI 更早平台化：ICPC 只有对/错两种反馈，可供继续细化的信息比 IOI 的子任务分数少得多。

### 5.6 组件贡献小结

把 Nano-CC 在 IOI 2025 的 Score@1 演进串起来看（论文引言 Figure 1(a) 与 §4.3-4.5）：

| 阶段 | IOI 2025 Score@1（原始分） | 说明 |
|:---|:---:|:---|
| Nemotron-3-Nano-30B-A3B（base） | 130（21.7%） | 预训练基座 |
| + SFT（3 epochs） | ≈280（46.7%） | 单样本增益主体 |
| + RL（GRPO，step 39） | 291（48.5%） | 小幅稳定增量 |
| + GenCorrect（5 轮） | 468.2（78.0%） | 超 2025 金牌线 438.3 |

同一管线套在 Ultra 上（SFT-only）：45.5% → 50.7%（304 分）→ 五轮 GenCorrect 后 502.0。**结论链：数据与 SFT 决定单样本能力基线，RL 在基线上小幅打磨前沿，GenCorrect 负责把模型潜力在真实提交预算内兑现——且兑现效率随基座变强而提高。**

## 第 6 章 IOI 2026 前瞻性评测

### 6.1 评测设置与资源

IOI 2026 分两天、每天一场 5 小时，共 6 道题；系统与人类选手受完全相同约束：**禁止联网、允许本地执行、每题最多 50 次提交且每分钟最多 1 次**。系统在题目公开前（live 比赛窗口内）运行，峰值使用 **760 张 NVIDIA GB300 GPU**。作者声明该系统并非 IOI 官方参赛者、运行未经 IOI 监督，得分不计入官方排名，属于非官方、无监督基准。

以 IOI 2025 作为开发基准选定下述适配，再在 IOI 2026 上做单次前瞻运行。

### 6.2 适配一：换用 GLM-5.2 作 SFT teacher

上一章结论指向「强基座 + 少量适配」，因此 live 运行聚焦 Ultra：只用 SFT（不用 RL——SFT 已提供主要增益，Ultra 规模 RL 超出算力预算）。先在 IOI 2025 上比较两个候选 teacher：

| System | IOI 2025 Score@1 | 平均生成长度（token） |
|:---|:---:|:---:|
| GLM-5.2 | 66.0% | 85,927 |
| DeepSeek-V4-Flash | 55.3% | 120,456 |
| Ultra-CC (GLM-5.2) | 59.4% | 84,244 |
| Ultra-CC (DeepSeek-V4-Flash) | 50.7% | 89,626 |

GLM-5.2 得分更高且输出更短（85,927 vs 120,456 token）；这个双重优势在 SFT 后依然成立——GLM-5.2 训练的 Ultra-CC 变体达到 59.4%（比 DSV4-Flash 变体高 8.7pp），平均输出也更短。**短输出意味着同推理预算内能生成更多候选**，这对 GenCorrect 的 200-候选池至关重要。live 运行选用 GLM-5.2 数据。

### 6.3 适配二：最终轮扩容到 1,000 候选 + 基于执行的选拔

前四轮与通用 GenCorrect 相同（200 生成 / 10 提交）。第 5 轮把生成预算提到 **1,000 个候选**（保留 10 次提交上限），并借鉴 GenCluster 用基于执行的选择流程：

1. 让模型产出 50 个题目相关的测试输入生成器与验证器；
2. 执行并用验证器过滤生成器，直到拿到 100 个有效测试输入；
3. 把所有能编译的候选解在这些输入上执行；
4. 让模型按题目的子任务判分标准写打分脚本；
5. 用该脚本排序，提交前 10 名。

动机：live 只有一次机会，而 IOI 2025/ICPC 2025 数据表明 Ultra-CC 在通用 GenCorrect 的连续轮次中趋于饱和，把第 5 轮的算力花在「更大的池子 + 执行级筛选」比再走一遍 200-生成流程更有价值。

### 6.4 适配三：NVFP4 量化换取吞吐

为在比赛窗口内跑完大规模候选池，用 NVIDIA Model Optimizer 的 NVFP4 recipe 对 Nemotron-3-Ultra 做后训练量化：用 SFT 混合中采样的 1,000 条 × 32,768 token 序列校准激活统计，导出 NVFP4 权重。论文 Table 3 报告性能/吞吐权衡（模型为 GLM-5.2 版 Ultra-CC，BF16 基线 59.4%）：

| Precision | KV Cache | Prefix | MTP | IOI 2025 Score@1 | 吞吐（tokens/s/GPU） |
|:---|:---|:---:|:---:|:---:|:---:|
| BF16 | — | — | — | 59.4% | 199.1 |
| NVFP4 | FP8 | Off | 5 | 52.8% | 736.8 |
| NVFP4 | BF16 | Off | 5 | 52.7% | 741.9 |
| NVFP4 | BF16 | On | 5 | 52.9% | 698.5 |
| NVFP4 | BF16 | On | Off | 53.5% | 345.9 |

几个观测：

- 各种 NVFP4 配置下 IOI 2025 Score@1 都收在 52.7%–53.5% 的窄区间（量化代价约 5.9–6.7pp vs BF16 59.4%）；
- 对齐 BF16 KV cache 与 prefix 后，开 MTP（Multi-Token Prediction）=5 把吞吐从 345.9 提到 698.5 tokens/s/GPU（近 2 倍），Score@1 只降 0.6pp（53.5%→52.9%）；
- live 选型：**NVFP4 + FP8 KV cache + 关闭 prefix caching + MTP 5** → 52.8% Score@1、736.8 tokens/s/GPU，相对 BF16 基线牺牲 6.6pp 换 **3.7×** 吞吐——这正是比赛窗口内跑 1,000-候选池的前提。

### 6.5 最终结果

论文 Table 4（下表为原表转写）：

| System | Score（/600） | 奖牌级别 |
|:---|:---:|:---:|
| 最高分人类选手 | 498.27 | Gold |
| 金牌线 | 361.12 | Gold |
| **Ultra-CC Live 比赛运行** | **535.40** | Gold |
| Ultra-CC 通用 GenCorrect 管线 | 521.72（495.0–545.8） | Gold |

live 得分 535.40：超金牌线 **174.3 分**、超最高分人类 **37.1 分**，且是在与人类相同的时限、提交平台与禁网条件下取得——据作者所知这是首个在 IOI 题目集上超过最高分人类的 AI 系统。赛后为语境化补充的通用五轮 GenCorrect 独立复跑均值 521.72（观察范围 495.0–545.8）：live 结果比该均值高 13.68 分（落在观察范围内），说明 6.2–6.4 的竞赛适配确有净收益，但并非不可复现的离群值；通用管线本身也已超过金牌线与人类最高分。

## 第 7 章 相关工作与定位

### 7.1 竞技编程 AI 的谱系

- **AlphaCode / AlphaCode 2**：领域专用训练 + 大规模采样、过滤与行为聚类（AlphaCode），更强模型 + 额外微调 + 学习式重排（AlphaCode 2）。GenCorrect 的聚类选择思想可溯源至此，但 AlphaCode 系不依赖执行反馈的迭代修正。
- **o1-ioi / o3（OpenAI）**：o1-ioi 以编码 RL + 手工推理管线拿下 IOI 2024 奖牌级成绩，o3 在官方提交限制下超过金牌线；OpenAI 与 Google DeepMind 还分别报告过 ICPC 2025 金牌级成绩。这些系统大多封闭、依赖专用模型，难以拆解各组件贡献——本文的归因实验正是针对这一缺口。
- **GenCluster（Samadi et al., 2026）**：首次用开源模型拿到 IOI 金牌，靠大规模生成 + 选择；本文第 5 轮扩充选择直接借鉴其基于执行的选拔流程。
- **DeepSeek-V3.2-Speciale**：报告 IOI 2025 与 ICPC 2025 双金牌；DeepSeek-V4-Flash/Pro 是本文 SFT teacher 与最强对比基线之一。
- **Nemotron-Cascade 2（Yang et al., 2026）**：仅 3B 激活参数即达到金牌级水平——与本文 Nano-CC 处在同一「小激活参数冲金」赛道；Table 1 中 Cascade-2-30B-A3B（37.2%/42.0%/45.6%）是 Nano-CC（48.5%/51.0%/71.6%）的直接参照系，显示本文的 SFT 数据规模与 RL 把同规模上限推高了一大截。

### 7.2 方法学坐标

- **合成推理数据**：OpenCodeReasoning 系列证明合成推理轨迹对竞技编程有效，其后续版本加入自批判与迭代细化——GenCorrect 的「模型自改进轨迹 + 执行反馈细化」与之一致，但把细化从训练时挪到了受提交预算约束的推理时。
- **可执行奖励 RL**：DeepSeek-R1 与 DAPO 建立了 verifiable-reward RL 的可扩展配方（无 KL 的 token 级 clipped 目标、leave-one-out 基线等），本文 RL 配置直接沿此路线。
- **执行反馈修正的可靠性**：Huang et al. (2024) 指出无外部反馈的自修正不可靠——GenCorrect 的每轮细化都锚定真实评测器的子任务分数，规避了该问题。

### 7.3 与既有基准的评测口径差异

本文所有对比模型分数均为自家 harness 复测（含 IOI 子任务计分细则），不直接引用各家报告；读者若与其他论文的同一模型分数对比，需注意评测 harness、子任务切分与采样次数口径可能不同。

## 第 8 章 讨论与局限

本章围绕论文自身的分析与坦承的局限展开，不再罗列实验数值，而是提炼增益的来源、结论的适用边界与遗留的开放问题，目标是区分哪些判断是稳固的，哪些受制于算力与评测口径而尚有保留。

### 8.1 SFT 与 RL 的增益结构

论文的最主要单样本增益来自 SFT，RL 阶段的增量相对较小。论文对这一增益结构的解释集中于奖励信号的可用性，可拆解为相互叠加的因素。

一方面，RL 采用二进制奖励，只有当同一组采样内同时存在成功与失败轨迹时，奖励才携带区分性信号；若组内全部成功或全部失败，奖励无法产生有效的学习梯度。

随着模型能力增强、题目通过率上升，能够提供有效信号的采样组自然收缩，RL 的可学空间随之变窄。这是奖励形式内生的限制，而非实现层面的缺陷。

另一方面是 credit assignment 的困难。竞技编程的推理轨迹长达 255K token 量级，而奖励只在轨迹终端给出一次。

在稀疏终端奖励下，把成败归因到真正起决定作用的中间决策——某个边界条件的处理、某个数据结构的选择——极为困难。

奖励在时间上距离它所评价的行为过远，学习信号大量耗散在与成败无关的轨迹片段上。轨迹越长，这一归因鸿沟越难跨越。

SFT 则不受上述限制：它直接模仿已验证成功的完整轨迹，无需经由奖励对长轨迹做逐步归因，在长轨迹、稀疏奖励的场景下天然更高效。

这解释了增益结构为何显著向 SFT 倾斜，也提示在竞技编程这类终端反馈任务上，模仿已验证的示范可能比从自身成败中探索更具样本效率。

从训练阶段的衔接看，这一结构还有先后相依的一面：SFT 把成功轨迹的覆盖推高之后，RL 所依存的组内成败对比空间随之被压缩，增量的边际递减与阶段顺序互为表里。

这一结构对解读后文训练曲线同样有意义：SFT 阶段的跃升与 RL 阶段的平缓并非实现上的失败，而是奖励信号结构下的预期形态。只要奖励保持二进制且终端化、轨迹保持长篇，该结构预计会重现。

综合而言，SFT 与 RL 的分工在论文中是清晰的：SFT 负责把能力抬升到可用区间，RL 负责在边际上修剪，测试时计算再把上述能力兑换为竞赛成绩。

### 8.2 测试时计算对规模优势的放大

论文观察到，测试时计算会放大基座规模的优势：强基座 Ultra 在并行采样与迭代修正（GenCorrect 闭环）的加持下，相对其他配置的领先进一步扩大。

其机制与测试时计算的组成环节直接相关。并行采样考验解分布的覆盖能力：更强的基座在困难题上命中完整正确解的机会更多，采样预算越大，这一尾部优势兑现得越充分。

迭代修正则考验利用反馈改进的能力：强模型对评测反馈的消化与转化同样更强，反馈回路进一步向强基座倾斜。

测试时计算因此不是中性的放大器，而是系统性偏向强基座的放大器。

值得注意的是放大的方向：测试时计算让强基座更强，而没有迹象表明它能让弱基座追平——预算越高，强弱分化越明显。

由此得出的方法论含义是：仅凭单样本成绩评估竞赛专用化 pipeline 会低估系统间的真实差距；竞赛成绩由基座、采样预算与反馈回路构成的整套系统共同决定，基座差异会经由测试时计算被放大而非抹平。

这也对评测报告实践提出要求：比较竞赛专用化系统时必须固定并明示测试时计算预算，否则成绩之间不可比。对后续在竞技编程上做模型选型的工作而言，固定预算的比较与单样本的比较可能给出不同排序。

这一效应与前述增益结构相互补：SFT 决定起点，测试时计算决定起点差距的兑现幅度；系统级评估因此必须同时报告基座与预算。

### 8.3 算力约束与消融的缺位

受算力约束，Ultra 规模的模型没有进行 RL 训练，RL 相关结论来自更小规模的配置；论文也未提供跨规模的全消融。

这留下了明显的开放问题：SFT 与 RL 的增益结构、pipeline 各组件的相对贡献，是否随规模发生质变，现有实验无法回答。

特别是，前述 RL 增量较小的归因——组内有效信号的收缩与 credit assignment 的困难——在更大、更强的基座上可能缓解，也可能加剧，相关结论的稳健性有待跨规模验证。

跨规模消融缺位的另一面是成本：RL 需要在长轨迹上反复采样并执行评测，规模越大开销越高，论文的取舍反映的是现实约束而非疏漏。

在这些缺口中，跨规模的 RL 对照最值得优先补齐：它直接决定"RL 增量较小"是普遍规律还是小规模现象，也决定 pipeline 的推荐用法是否随规模调整。

在补齐这类消融之前，"SFT 为主、RL 为辅"应视为当前规模下的经验观察，而非可外推的规律。

### 8.4 Live 结果的性质与边界

对 IOI 2026 的 live 结果需要作性质上的限定，论文自身对此有明确的表述；离线评测（IOI 2025、ICPC 2025）与 live 结果同属作者自建评测管线的产物，同样不视为官方赛事记录。

首先是系统级对比而非等资源对比。模型的"参赛"是包含并行采样、评测反馈与迭代修正在内的完整系统，与人类选手在时间、提交预算与协作条件上均不对应。

live 成绩的差距因此衡量的是系统与人的差距，不能解读为模型与人类的等资源能力对比；成绩证明的是当前测试时计算预算下整套系统的表现，而非模型在与人相当的限制条件下的独立能力。

其次是监督与排名的缺席。评测未经 IOI 官方监督，结果亦未计入官方排名；奖牌线结论是作者评测口径下的估计，而非官方认证的赛事成绩。

在官方语境下，这些成绩只能作为参考性对照：论文报告它们是为了度量系统的竞赛能力，而非主张模型取得了正式名次。

结合统一的自建 harness 复测政策，所有 live 数字应理解为统一评测管线下的可复现估计，而非赛事记录。

引用这些成绩时应连同口径一并说明，避免与人类选手的官方成绩直接并置。

这些限定并不削弱结果的价值——系统级表现本身就是对竞赛能力的严格度量——但它们约束了结论的表述方式。

### 8.5 向竞技编程之外的可迁移性

论文的 pipeline 深度依赖竞技编程的特殊条件：存在可执行的评测器，反馈可以自动化产生；题目难度谱系清晰，便于按难度编排训练课程；subtask 分数或二进制判定构成天然可用的奖励信号。

这些条件在其他推理领域并不普遍。缺少客观且可自动化反馈信号的领域，可执行奖励 RL 与反馈驱动的迭代修正都难以照搬。

凡是具备可执行评测器与自动化反馈的任务，都是最自然的迁移候选，但收益幅度仍需逐一实证。

论文的结论因此限定在竞技编程及其近似领域之内。向通用推理任务的外推是开放的实证问题，而非可默认成立的推论。

### 8.6 开放性与发布计划

训练语料因第三方的再分发限制不发布，这是可复现性上最直接的缺口。

数据构成、难度分布与去重细节因此无法被社区完整审计，训练侧的结果只能被间接检验。

作为补偿，论文计划通过 NeMo-Skills 发布竞赛专用化 checkpoint 与推理、评测 recipes，使推理侧与评测侧的复现成为可能；训练侧的复现则依赖社区在自有语料上重建。

发布安排的实际意义在于：评测 recipes 使协议可被第三方独立执行，checkpoint 使推理侧结果可被独立复核，覆盖了训练数据之外的复现链路。

算力约束同样塑造了发布计划的形态：优先释放可验证性最高的评测与推理侧资产，训练侧留待社区。

整体而言，论文以可复现的评测协议与即将发布的模型产物，部分对冲了训练数据不可发布带来的透明度损失，而数据侧的完全验证仍有待独立重建。
