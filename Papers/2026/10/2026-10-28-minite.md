## 第 1 章 概述

### 1.1 一句话定位

用 NVFP4 等原生低位格式加速 LLM 的 RL 后训练时，采样与训练分别运行在两个独立引擎（sampler 与 learner）上；论文发现即使两侧权重版本与数值格式完全匹配，跨引擎的数值执行仍不一致，且该不一致会经 importance ratio 直接进入 RL 优化目标。miniTE 是一个轻量框架，将执行诊断、跨引擎数值对齐与高效原生 W4A4（4-bit 权重、4-bit 激活）GEMM 计算组合在一起：在不修改 RL 目标函数的前提下提升数值执行一致性，并以低实现开销兑现原生低位计算的收益；长程 RL 实验基于 Qwen3-30B-A3B，训练稳定性与基准成绩接近 BF16，评估质量优于 naive Transformer Engine (TE) NVFP4。

### 1.2 核心贡献

**贡献一：执行鸿沟的系统诊断。** 论文用三层控制实验定位差异来源：冻结策略（排除更新因素）、路由条件化（matched routing 下仍有 FC1/FC2 残差）、缩放对照（仅改 sampler 外层 scale 的 per-tensor→per-token 不消除差异）。结果显示：即使权重版本与数值格式匹配，learner 与 sampler 之间仍存在数值执行差异，NVFP4 将 |Δlog p| P99 从 BF16 的 0.1271 nats 放大到 0.2911 nats。由此提出「执行规范」（scale 域、舍入、layout、cast 位置、router 系数位置）概念——它超越位宽与 expert ID，是诊断与实现的正确单位。

**贡献二：实用的原生 NVFP4 RL 路径。** per-token 外层 scale 的 W4A4 专家前向 + BF16 backward（直通近似，∇X≈GW、∇W≈GᵀX），不改 RL 目标函数。长程 RL 实验（DAPO-Math-17k、GRPO、1000 步）在 Qwen3-30B-A3B 上稳定训练，四个数学基准全部超过 naive TE NVFP4。注意「native W4A4」仅指专家前向 GEMM；attention、非专家模块、backward 与 optimizer 状态保持高精度。

**贡献三：量化与 grouped GEMM 的联合设计。** 共享 producer–consumer 表示（FP4 codes、block scales、outer scale 打包直写连续缓冲）、统计随激活传播（FC1 的 sort+amax 融合，替代 pad 后扫描；FC2 的 amax 来自 router 加权激活 producer）、原生块缩放累加 + epilogue FP32 重缩放（论文式 5）。expert forward 相对 TE U3045 取得几何均值 2.46× 加速，使完整 learner 更新吞吐达到 1.39× BF16。

## 第 2 章 研究背景与动机

### 2.1 RL 后训练的双引擎结构与数值差异的传播

RL 后训练（论文采用 GRPO 类算法，语料 DAPO-Math-17k）天然是双引擎结构：sampler（rollout/serving 引擎，论文环境使用 SGLang）以温度 1.0 采样 responses 并记录 token 级 log-prob（logp_old）；learner（训练引擎，基于 Megatron 栈）重新前向计算当前策略 log-prob，构造 policy ratio 并做梯度更新。两个引擎是不同的软件栈：同一份权重、同一个格式名，在两侧并不保证产生相同的数值执行。

数值差异之所以致命，在于它直接进入优化目标。论文的训练目标为 TIS-corrected clipped policy gradient（式 1）：policy-ratio clip 区间 [0.80, 1.28]，并以截断重要性采样（TIS）权重 w_t 修正 learner 重算的 old log-prob 与 rollout 时记录值之差：

$$\mathcal{J}(\theta)=\mathbb{E}\left[\frac{1}{|o|}\sum_{t=1}^{|o|} w_t\cdot\min\left(r_t(\theta)\,\hat{A}_{o,t},\ \mathrm{clip}\left(r_t(\theta),\,0.80,\,1.28\right)\hat{A}_{o,t}\right)\right]$$

$$r_t(\theta)=\exp\left(\log\pi_\theta(o_t)-\log\pi_{\mathrm{old}}(o_t)\right),\qquad w_t=\mathrm{clip}\left(\exp\left(\log p_{\mathrm{old}}^{L}-\log p_{\mathrm{old}}^{R}\right),\,0,\,2\right)$$

其中 L 表示 learner 重算、R 表示 rollout 引擎记录，w_t 与 policy-ratio clipping 相互独立。论文将两引擎的数值差定义为（式 2）：

$$\delta_{\mathrm{num}}=\log p^{L}(o_t)-\log p^{R}(o_t),\qquad \rho_{\mathrm{num}}=\exp\left(\delta_{\mathrm{num}}\right)$$

即 w_t = clip(ρ_num, 0, 2)。|Δlog p| 的尾部统计（32 prompts / 69,088 matched tokens）显示 NVFP4 下该差异显著大于 BF16（P99 0.2911 vs 0.1271 nats），且 NVFP4 的 clip potential 达 1.203%（BF16 为 0.627%）：数值执行差异不再只是精度损耗，而是被 clipping 与重要性比值放大成优化层面的偏置——这就是「执行鸿沟」。

### 2.2 NVFP4 数值格式与「执行规范」

NVFP4 是两级缩放的 4-bit 浮点格式（式 3）：每个值用 E2M1 编码（最大可表示幅值为 6），每 16 个值共享一个 E4M3 block scale，再套一层 FP32 外层 scale：

$$\hat{x}=\mathrm{E2M1}\left[\frac{x}{s_b\cdot s}\right]\cdot s_b\cdot s,\qquad s_b=\mathrm{E4M3}\left(\frac{\max_{i\in B}|x_i|}{6}\right),\ \ |B|=16,\qquad s\in\mathrm{FP32}$$

miniTE 的原生路径取 per-row 外层 scale：s = max/(6·448)（论文式 4，448 为 E4M3 最大幅值）。

格式名并不唯一决定执行结果。论文的核心概念是「执行规范」（execution recipe）：在位宽与格式之外，scale 的计算域（per-tensor / per-token / per-row）、舍入模式、数据 layout、cast 位置、router 系数的施加位置等选择，同样决定一条 GEMM 的逐位输出。第 3 章的诊断将证明：仅匹配权重版本与格式名不足以对齐两个引擎，必须显式记录并对齐执行规范；这也是 miniTE 框架（第 4 章）将执行规范作为一等公民接口的原因。

### 2.3 三种数值比较的区分与相关工作定位

论文严格区分三种容易混淆的比较：

- **量化误差（quantization error）**：同一执行栈内，低位格式对全精度参考的逼近偏差，如 NVFP4 前向 vs BF16 前向；
- **跨栈执行差（cross-stack execution difference）**：不同引擎（learner 与 sampler）在相同权重与相同格式名下产生的差异——本文的诊断焦点；
- **实现差（implementation difference）**：同一格式在同一引擎内不同实现版本/算子选择带来的差异（如 TE 不同版本之间，文中以 TE U3045 为对照）。

与相关工作的定位差异：QeRL、Jet-RL、QUADS、QaRL 等低位/量化 RL 先行工作聚焦量化误差与低位训练的稳定性及吞吐，未将跨引擎数值执行一致性作为独立问题处理；Miles 等低精度训练系统面向通用效率，不针对 RL 双引擎结构下的执行规范。另一线执行失配研究（off-policy 分析、序列级 ratio、执行对齐参考、确定性 kernel）在全精度域处理执行差异，miniTE 则将其推进到原生 NVFP4 域，并落到 W4A4 grouped GEMM 内核的实现层面——诊断、对齐与内核设计三者闭环，是论文区别于上述各线的位置。
## 第 3 章 执行鸿沟诊断

miniTE 的第一项贡献不是加速，而是把「learner 与 sampler 之间的数值差异」从工程直觉提升为可测量、可定位、可归因的对象。论文设计了一组逐层收紧的控制实验，全部基于 Qwen3-30B-A3B-Base 冻结检查点（step 0）的 teacher-forced 评分：两台引擎接收完全相同的 token ID，在相同评分上下文下对同一 chosen-token 序列打分，从而把「执行差异」与「权重滞后」「采样随机性」彻底分离。

### 3.1 冻结策略：鸿沟在优化开始之前就存在

定义数值执行差异（式 2）：

$$
\delta^{\mathrm{num}}_{t}=\log \pi^{L}_{\theta}(a_{t}\mid s_{t})-\log \pi^{R}_{\theta}(a_{t}\mid s_{t}),\qquad \rho^{\mathrm{num}}_{t}=\exp(\delta^{\mathrm{num}}_{t})
$$

其中 $\pi^{L}_{\theta}$ 与 $\pi^{R}_{\theta}$ 是同一参数版本下 learner 与 sampler 的策略。测量规模：32 个 prompt（长度桶 512/2,048/4,096），共 69,088 个匹配 token；置信区间用 2,000 次 prompt-cluster 配对 bootstrap。

| 条件 | \|Δlog p\| P99 | Ratio P01 | Ratio P99 | Clip potential |
|:-----|:---:|:---:|:---:|:---:|
| BF16 | 0.1271 | 0.9471 | 1.0489 | 0.627% |
| NVFP4 | 0.2911 | 0.8933 | 1.1243 | 1.203% |
| Per-token 早期候选 | 0.3179 | 0.8745 | 1.1152 | 1.282% |

（来源：论文 Table 4，附录 C）

关键观察有三层：

- **NVFP4 放大尾部**。|Δlog p| 的 P99 从 BF16 的 0.1271 nats 增至 0.2911 nats，配对增量 0.1641（95% CI [0.1311, 0.2005]）。即在任何优化器更新发生之前，四比特量化已经把跨引擎 log-probability 尾部推离 BF16 的「跨引擎地板」。
- **数值差异直接触碰优化机制**。仅由数值差异构成的 ratio 超出分析 clipping 界限（[0.80, 1.28]）的 token 比例：BF16 为 0.627%，NVFP4 为 1.203%——近乎翻倍。这些是 clipping 电位（clipping potential），实际训练还取决于 advantage 与 TIS 修正，但通道已经打开。
- **同栈自比对是逐位精确的**。within-stack 自比较 bitwise 一致，说明差异确实来自跨引擎执行而非随机性。

### 3.2 路由条件化：匹配了 expert 分配仍不收敛

第一反应是把差异归咎于 MoE 路由的不一致——两个引擎选了不同专家，输出自然不同。论文的第二组控制实验排除了这一解释的充分性：在观测层**固定 expert 分配**（set-match = 1.0，无非法 expert），保留该层自然累积的输入，FC1（相对 L2 差异）仍达 0.0381–0.6124（峰值在 layer 32），FC2 达 0.0810–0.7624（峰值在 layer 40）。定位实验用 12 个 prompt、11 个深度（layers 0, 8, 14, 15, 16, 17, 18, 24, 32, 40, 47），共 33 个层运行。

对照数据（自然路由下的失配幅度）：

| 指标 | BF16 | NVFP4 |
|:-----|:---:|:---:|
| 自然路由不一致（相对） | 0.0459–0.5938 | 0.0459–0.7559 |
| MoE 输出相对 L2 差异 | 0.0072–0.2072 | 0.0269–0.2831 |

（来源：论文 §3.2 与附录 C）

即：固定了目标层路由后，运算子本身的差异依然存在；且随深度的发散是非单调的（曲线存在局部收缩），说明这不是简单的误差累积。

### 3.3 更细的 scale 不是解药

第三组控制只把 sampler 的激活外层 scale 从 per-tensor 改为 per-token：FC1/FC2 差异**完全不变**（Table 5：per-tensor rollout 与 per-token rollout 的 FC1 GEMM 相对 L2 均为 0.03767，FC2 均为 0.08064，差值 0.00000）；P99 变化的 95% CI 为 [−0.2231, 0.1517]，含零。更早的 per-token 候选（nvfp4_cursor2 learner + per-token rollout）P99 反而比标准 NVFP4 更高（0.3179 vs 0.2911，增量 0.0268 nats，95% CI [0.0017, 0.0495]），clip potential 增加 0.080 pp。

结论：**仅换 scale 粒度不能建立跨引擎一致性**。NVFP4 这个格式名下藏着 scale 域、舍入指令、归约顺序、padding、router 权重与输出 cast 的进入位置等一整套选择——论文称之为「执行规范」（execution specification）。位宽与 expert ID 的一致只是必要条件。

### 3.4 共同输入回放：把边界推到算子级

附录 C 的共同输入回放（common-input replay）进一步把比较边界推到算子级：在 MoE 模块入口捕获输入 $h_L$（learner）与 $h_R$（sampler），交叉执行四个组合 $F_L(h_L), F_L(h_R), F_R(h_L), F_R(h_R)$，用参考归一化度量（式 7）分离「输入差异」$I_j$ 与「执行差异」$E_j$：

$$
R(A,B)=\frac{\lVert A-B\rVert_{F}}{\lVert B\rVert_{F}},\qquad I_{j}=R\bigl(F_{L}^{j}(h_{L}),F_{L}^{j}(h_{R})\bigr),\qquad E_{j}=R\bigl(F_{L}^{j}(h_{R}),F_{R}^{j}(h_{R})\bigr)
$$

| 设置 | Layer | R(h_L,h_R) | FC1 I₁ | FC1 E₁ | FC2 I₂ | FC2 E₂ |
|:-----|:---:|:---:|:---:|:---:|:---:|:---:|
| BF16 | 0 | 0.1222 | 0.1231 | 0.1606 | 0.1103 | 0.1609 |
| BF16 | 24 | 0.7353 | 0.6049 | 0.1264 | 0.8211 | 0.2276 |
| BF16 | 47 | 0.4666 | 0.3425 | 0.1090 | 0.8957 | 0.2402 |
| miniTE | 0 | 0.0030 | 0.0220 | 0.0575 | 0.0383 | 0.0931 |
| miniTE | 24 | 0.2603 | 0.2349 | 0.0664 | 0.3895 | 0.1589 |
| miniTE | 47 | 0.1632 | 0.1501 | 0.0587 | 0.1541 | 0.0870 |

（来源：论文 Table 6，附录 C。miniTE 行是回放环境（miniTE b641179 + SGLang 12344e4d，EP2/list packing）下的表现）

在 layer 0 的共同输入下，miniTE 路径仍保留 FC1 0.0575、FC2 0.0931 的残差——注意 FC2 的比较包含了此前 FC1、激活与组合的差异，并非孤立的 FC2 GEMM 算术。这组数字划定了「对齐后仍剩什么」的基线，也说明彻底消除残差需要完整的执行路径匹配（§5.4 的 strict 参考）。
## 第 4 章 miniTE 框架：执行规范、原生数值路径与联合算子设计

诊断的结论决定了设计的形状：既然差异藏在「执行规范」里，框架就必须把这份规范显式化、可配置、可检验。miniTE 由三块组成——执行规范与诊断参考、原生 NVFP4 学习路径、量化与 grouped GEMM 的联合优化（论文 Figure 2）。

*图2：miniTE 框架把「执行规范」（scale 域/舍入/layout/cast 位置）连接到诊断接口（操作数、专家输出、策略评估三个边界）与原生专家计算数据流（打包 FP4 codes/scales 直供 Tensor Core 的 grouped GEMM）*

### 4.1 执行规范与两个互补参考

一份执行规范记录：量化操作数、内层 block 与外层 scale 域、scale 的 dtype 与舍入、Hadamard 变换与随机舍入开关、逻辑 layout 与 padding、专家路由与打包、累加与 epilogue 精度、以及 GEMM 周围的非量化算子。比较时固定权重版本、token ID 与评分上下文，把 codes 与 scales 解码到公共 layout。

框架提供两个互补参考：

- **严格执行参考（strict execution reference）**：把 learner 的 kernel、公式、归约顺序匹配到 sampler（含周边归一化与通信路径），保留 NVFP4 专家前向与 BF16 梯度。它是诊断用的「可行动对齐基准」——§5.4 显示其跨引擎 log-prob 差异约 $10^{-8}$。
- **算子参考（operator reference）**：在固定 recipe 与共同输入下对比初始实现与优化实现，检验 API/layout 变换是否保持了量化操作数与输出。实用 learner 路径的每次实现改动都要过这一关。

### 4.2 原生 NVFP4 学习路径

**逐 token 外层 scale。** 每个 dispatched activation 行拥有自己的外层 scale，消除对其他 token 极值的依赖。对专家 $e$、token $t$ 与权重输出行 $n$：

$$
g^{x}_{e,t}=\frac{\max_{k}|X_{e,tk}|}{6\cdot 448},\qquad g^{w}_{e,n}=\frac{\max_{k}|W_{e,nk}|}{6\cdot 448}
$$

（式 4；6 为 E2M1 最大幅值，448 为 E4M3 最大幅值）。内层为长度 16 的 E4M3 block scale + E2M1 codes（同式 3）。该路径禁用 Hadamard 变换与随机舍入。上下文交换测试（context-swap）验证了逐 token 依赖的实际效果：固定 8 个目标行、更换 128 行 FC1 输入中的伴随行，miniTE 路径在全部 6 次交换中目标行 FP4 codes 与 GEMM 输出逐位不变；per-tensor 参考（启用 RHT）6 次中 5 次发生改变（Table 7，附录 D）。

**原生累加与 epilogue 重缩放。** 外层因子与归约下标 $k$ 无关，因此可以移到原生块缩放累加之后（式 5）：

$$
U_{e}=\operatorname{MMA}_{\mathrm{NVFP4}}(\bar{X}_{e},\bar{W}_{e}^{\mathsf{T}}),\qquad Y_{e,tn}=\operatorname{cast}_{\mathrm{BF16}}\!\left(g^{x}_{e,t}g^{w}_{e,n}U_{e,tn}\right)
$$

其中 $\bar{X}$、$\bar{W}$ 是直接供给 Tensor Core 的打包 FP4 操作数与 E4M3 block scales。epilogue 在 BF16 输出 cast 前以 FP32 广播外层因子（附录 D 给出乘法顺序：$Y_{mn}=\operatorname{BF16}[2688^{-2}a^{W}_{n}(a^{X}_{m}U_{mn})]$，式 8）。这把缩放规则接入原生算术，而无需物化解码后的 BF16 操作数。

**独立的 backward 精度。** 默认 backward 用直通近似（straight-through），以保存的原始 BF16 激活与权重做 BF16 GEMM：

$$
\nabla X_{e}\approx G_{e}W_{e},\qquad \nabla W_{e}\approx G_{e}^{\mathsf{T}}X_{e}
$$

这一选择把前向 recipe 与 backward 精度解耦：§5.4 的实测显示 BF16 backward 在全部 8 个模块格中快于 MXFP8 backward（几何均值约 1.21×），且对 FP32 参考的最大梯度相对 L2 差异为 0.001663（dgrad）/0.001663（wgrad），远小于 MXFP8 的 0.037626/0.037653。

**MoE 组合与 RL 集成。** learner 把 router 概率施加于 SwiGLU 激活之后、FC2 之前，再进行专家组合；padding、量化与 cast 保持此顺序。非专家模块保持其配置的高精度；权重转换与同步把 learner 连接到带逐 token 激活缩放的 NVFP4 sampler，现有 TIS 修正的 RL 流水线原样消费两边的策略评估——**RL 目标函数未被修改**。注意「原生 W4A4」仅指专家前向 GEMM：attention、非专家模块、backward 与 optimizer 状态保持更高精度。

### 4.3 量化与 grouped GEMM 的联合设计

路由式专家计算的成本不只是矩阵乘：操作数准备、表示转换与调度同样占大头。miniTE 把量化器与 grouped GEMM 优化为一条连通数据流：

- **共享 producer–consumer 表示。** 参考实现让量化器返回 expert 视图/列表，grouped GEMM 再重建参数。miniTE 直接把打包的 FP4 codes、block scales 与外层 scale 信息写进 GEMM 消费的连续缓冲，设备侧 offset 描述专家边界，元数据与工作区复用，支持空组。消除两个分组接口间反复的切分与参数准备。
- **统计随激活传播。** FC1 参考路径是 sort→pad(X)→amax 扫描→quant；miniTE 改为 **sort+amax 融合→pad(X, amax)→quant**——在置换时收集极大值、对激活与统计量一起 padding，免去对 padded 行的额外扫描。FC2 的极大值则直接取自 router 加权激活的 producer，与量化器实际消费的张量一致（与 COAT 的 group scaling 思想同源，但跨过了 MoE 置换、padding、加权激活与 NVFP4 两级 scale）。
- **Layout 与原生 GEMM 执行。** 融合的 scale layout 准备直接供给 Tensor Core 所需格式；FC1/FC2 按各自归约长度选 GEMM 配置，耦合 tile 选择与 tensor memory 分配。优化路径合并稠密表示、置换融合与 amax 复用。

实现层面通过公共 expert-computation 接口替换专家 grouped-linear 模块接入；量化 recipe 与 backward 精度独立可配，§4.1 的操作数/专家输出/策略评估三个边界为每次 recipe 或 kernel 改动提供可复用的检查点。

### 5.4 执行参考与设计验证

- **strict 参考**：匹配 kernel、公式与归约顺序（含归一化与通信路径）、无 TIS 的严格配置记录到约 $10^{-8}$ 的跨引擎 log-prob 差异，并在未对齐运行退化的区间内保持 reward——证明原生 FP4 计算与稳定学习可以在「执行级对齐」下共存。
- **数值保持**：§4.4 的 28 项逐位 API 检查与融合 layout 零偏差检验全部通过。
- **backward 精度的独立选择**：固定专家前向，BF16 backward 在全部 8 个模块格中降低前向+反向延迟（几何均值约 1.21×），梯度对 FP32 参考的最大相对 L2 差异 0.001663（BF16）vs 0.037653（MXFP8），时延与精度证据同向支持 backward 精度独立于 W4A4 前向 recipe 选择。

### 6.3 诊断工具的设计价值

miniTE 暴露的可配置项与三个复用边界（操作数 / 专家输出 / 策略评估）构成一套「低位训练数值开发环境」：任何 recipe 或 kernel 改动都可以在相同边界上重复 §3 的测量。对想在其他模型/格式上复现这类诊断的读者，论文给出的最小组合是：冻结检查点 + teacher-forced 同序列打分（分位数与 clip potential）+ 路由条件化的逐层定位 + 共同输入回放（I/E 分解）。

## 第 7 章 局限性与延伸阅读

### 7.1 论文自述局限

- **质量仍低于 BF16**：五任务均值落后 2.49 pp；strict 执行也未消除 E2M1/E4M3 本身的量化误差，且现有证据无法把剩余质量差距分解为「量化误差」与「残余执行差异」的占比。
- **端到端效率未证明**：colocated 测量只覆盖 learner + 权重同步两级（miniTE 合计 97.82 s vs BF16 56.98 s），不含 rollout； learner→sampler 边界的重复转换与打包（BF16→NVFP4 转换使同步膨胀 5.56×）被识别为首要集成瓶颈。
- **证据覆盖面**：单一 MoE 模型（Qwen3-30B-A3B）、每配置单次训练 run、实现增益仅在 Blackwell（B300/GB200）上评估；跨模型、跨任务、独立训练 seed 与其他硬件平台留作未来工作。论文甚至保留了 GB200 短窗口实验中「约 18.3 的初始 loss 无法解释」这类负结果记录，并明确该窗口只提供计时证据。

### 7.2 与相关工作的位置

- **原生低位学习**：Microscaling Formats（MX）规范、QLoRA（4-bit 存储 + BF16 计算）、Quartet（原生 MXFP4 前向与梯度 GEMM）、NVFP4 预训练、Composer 2、Miles（per-token NVFP4 + 高精度 backward + 量化器一致）——miniTE 的差异在于研究**残余的跨引擎执行差异**与原生专家路径的实现成本。
- **量化 RL**：QeRL（量化 rollout + LoRA）、Jet-RL（FP8 训练与 rollout 统一）、QUADS（learner W4A16 QAT + sampler 激活残差补偿）、QaRL（低位前向 + 序列级 trust-band）——miniTE 保留现有 TIS 修正的 RL 目标，聚焦 native W4A4 专家前向 + BF16 backward 的组合。
- **执行失配与路由**：off-policy 分析、序列级 ratio、执行对齐参考、FP16 舍入精度研究、选择性 router 精度与路由重放、确定性 kernel（batch-invariant）——miniTE 的贡献是在「匹配目标层路由分配」之后仍能定位残差差异。

### 7.3 阅读建议

这篇论文的价值排序值得注意：它真正的贡献不是 1.39× 的加速数字（naive NVFP4 是 0.945×，四比特本身什么也不保证），而是把「执行规范」确立为低位 RL 的正确诊断单位——scale 域、舍入指令、归约顺序、cast 位置这些格式名之下的自由度，才是跨引擎一致性的决定变量。对做低位训练系统的读者，§3 的诊断协议（冻结策略分位数 → 路由条件化 → 共同输入回放）与 §4.3 的 producer–consumer 联合设计比任何单项 benchmark 都更可迁移；对做 RL 算法的读者，Table 13 的权重同步膨胀（9.94 s → 55.26 s）是量化 RL 落地时最容易被忽视的成本。
