## 第 1 章 概述

### 1.1 一句话定位

本文提出了一种**字节精确的 KV 缓存嫁接（KV-State Grafting）** 机制，使冻结的小模型在不更改权重和不增加加速器预算的前提下，同时变得更智能（AIME 2025 从 80.0% 提升至 93.3%）和更便宜（复发场景仅用 61 个解码 token 解决原本 401K token 无法解决的问题），将验证知识以字节精确的 KV 状态持久化并按需嫁接。

论文的核心论题由两个可测量的声明支撑：
**能力声明**——冻结 Gemma-4-12B 嫁接后解决原来无法解决的问题（12B hold-out: 5/7, 31B: 7/7）；
**成本声明**——复发场景 61 token 解决 401K token 解决不了的问题（6,574x 更少 token）。两个声明通过同一机制实现：字节精确性确保能力归因清洁、成本计算诚实。本文是 Corbenic AI 系列第三篇，前序为 Merlin 去重引擎（arXiv:2605.09990）和 RAG 精确去重分析（arXiv:2605.09611）。

### 1.2 核心贡献

1. **字节精确 KV 状态嫁接（Taliesin）**：首次公开演示了字节精确、持久、可移植的 KV 缓存嫁接机制。在固定确定性配置下，嫁接后的 logit 向量与重新计算的结果字节级一致（SHA-256 相等、KL 散度为 0、100% argmax 一致）。验证覆盖 CPU 构建、CUDA 构建和真实 GPU（Gemma-4-12B），以及跨上下文嫁接（不同推理进程间）。

2. **精确性数值边界刻画**：通过对抗性测试证明，自身位置（own-position）嫁接是 32 位浮点旋转位置编码（RoPE）模型上唯一可达字节精确性的操作点；偏移嫁接受浮点舍入残差限制（不可约的约 0.01 KL）。论文逐一排除七种候选解释：半精度舍入、滑动窗口缓冲、偏移量级、双旋转路径、频移不匹配、大角度参数缩减误差和 reduction-tree 重关联。

3. **验证知识飞轮（Galahad）**：一次求解→外部验证（执行代码确认输出匹配已知答案）→KV 状态持久化→按需路由（Routed Retrieval）→嫁接→零开销读取。形成"一次求解，不再重付"的经济模式。路由而非扁平块合并是关键设计决策——所有方法同时存在时模型混淆（召回 5/8），路由到单个块后修复。

4. **上下文扩展**：KV 块作为磁盘文件，使 32K token 的服务窗口扩展至 2.85M token（87 倍），零额外加速器内存，任意深度访问时间一致（约 0.29 s 恢复）。

5. **经济性反转**：通过验证知识的复用，买一个百分点准确率的成本约为传统采样投票方法的 1/50。同时发现大 MoE 模型并不总是更便宜——其 per-token 廉价被啰嗦消耗吞噬。

### 1.3 关键结果速览

- Gemma-4-12B 在 AIME 2025（模型训练截止日期之后的竞赛题）：冻结裸模型 80.0% → 嫁接验证库后 **93.3%**，超过其 31B 兄弟模型的厂商锚定值（89.2%）
- 复发场景：8 道基础模型从未能解决的问题，嫁接后 **61 个解码 token** 全部正确回答（原最佳基线 401,026 token 解决 0 道）
- 推理速度：冷预填充（11,994 token）需 1,547 ms → 热嫁接（1 token）仅 **18.1 ms**，加速比 **85.6x**
- 上下文扩展：从 32K token 服务窗口扩展至 **2,854,766 token**（87 倍），零额外加速器内存，任意深度访问耗时一致（0.29 s 恢复）
- 能量节省：复发场景能耗降低约 **3,000–8,700 倍**
- **跨架构验证**：RTX 5090（Blackwell 消费级）和 B200（Blackwell 数据中心级）复现字节精确性（通过预注册 replay），H100 完成功能验证（7/7 transfer, 8/8 recurrence）但**未测量字节级精确性**

## 第 2 章 研究背景与动机

### 2.1 现有范式的成本困境

当前大语言模型的能力提升几乎完全依赖规模扩展：更大的语料、更多的参数、更庞大的集群。这种范式并非错误，但代价日益成为瓶颈——单次大规模训练耗能数百吨碳当量。而在推理端，有一个更安静但更普遍的浪费：**相同的上下文被一次次预填充、计算注意力、然后丢弃**，因为标准推理栈将计算出的 KV 缓存视为临时状态。

两种成本叠加：使模型更智能的成本（重训/微调）+ 使用智能模型的成本（每次重算上下文）。

### 2.2 现有状态复用方法的分层

现有 KV 状态复用工作可归为四类：

- **近似且短暂**：原生提示缓存、前缀复用、RadixAttention。快速但限于同一服务器进程，滑动窗口模型仅从稀疏检查点恢复。
- **近似且持久**：CacheGen（KV 压缩与流式传输）、KV 缓存量化。有损压缩后存储，恢复后精度损失。
- **精确但短暂**：同一 session 内的精确缓存，session 结束即丢弃。
- **功能级嫁接（FCGRAFT, Chun et al. 2026）**：缓存已验证代码骨架函数的 KV 状态，宏级别任务自适应复用，同名但无字节精确保证。

本文填补的是**「精确且持久」**的空白：KV 状态可精确捕获、持久化到磁盘、跨会话跨机器恢复，且恢复后的行为与重新计算不可区分。

### 2.3 现有方法的不足

具体来看每类方法的局限性：

- **原生提示缓存（Prompt Cache / RadixAttention）**：快速但服务进程重启后丢失；滑动窗口模型仅从稀疏检查点恢复，同样的提示重发可能仍重新评估大部分内容。
- **近似 KV 压缩（CacheGen / KV 量化）**：有损压缩后的状态无法保证输出与新鲜计算一致，能力提升无法可靠归因。
- **RAG（检索增强生成）**：外部知识以 token 形式注入提示前缀，但每次调用都被重新读取和注意力计算，成本持续累积而非一次性摊薄。
- **权重微调（Fine-tuning / LoRA）**：持久且推理时无额外开销，但不精确（不是"字节精确"）、不能以单条事实为粒度组合、且每次安装需要一次训练运行。
- **功能级缓存嫁接（FCGRAFT, Chun et al. 2026）**：缓存已验证代码骨架函数的 KV 状态，在宏观层面上实现任务自适应复用，但不提供字节精确保证。

### 2.4 为什么精确性是承重属性

如果嫁接只是近似状态，能力提升无法归因——是知识带来的提升还是近似噪声的漂移？复发场景的缓存答案能否无损通过往返传输？字节精确性同时消除这两个疑虑：**嫁接状态 = 模型已阅读该知识**，因此验证库可以作为一个学习单位，一个带验证库的冻结 12B 模型在权重层面未变，但在行为层面是一个不同的、更强大的预测器（KL=0）。

精确性还带来了一个实用优势：KV 块是一个普通文件，可以复制到新服务器上嫁接后字节一致、无需重新求解即可正常工作。这在多服务器部署和灾难恢复场景中有重要价值。

## 第 3 章 字节精确 KV 状态嫁接（Taliesin）

### 3.1 字节精确性的形式定义

令冻结权重和固定数值精度下的模型处理 token 序列，在指定位置产生 logit 向量 $L \in \mathbb{R}^{V}$（$V$ 为词表大小）和相应的内部 KV 状态。嫁接操作将之前捕获的状态安装到新的推理上下文中，在对应位置产生 logit 向量 $\hat{L}$。嫁接称为字节精确的，当且仅当：

$$
\text{SHA-256}(L) = \text{SHA-256}(\hat{L})
$$

即两个 logit 向量在原始字节级别完全相同。作为分布推论，记 $P = \text{softmax}(L)$ 和 $\hat{P} = \text{softmax}(\hat{L})$，字节精确性蕴含：

$$
D_{\text{KL}}(P \parallel \hat{P}) = 0, \quad \arg\max P = \arg\max \hat{P}
$$

论文在所有实验中同时验证了字节级相等性（SHA-256）和分布级相等性（KL 散度），两者均须在每次试验中成立。

### 3.2 位置一致性与精度控制

嫁接的关键约束是**位置一致性**：块必须在其捕获的位置布局处恢复。具体来说，块占据活动上下文的 $[0, n)$ 位置范围，新的查询在位置 $n$ 之后计算。"跨上下文"指恢复到一个不同的推理进程（新进程、新服务 slot、或同架构的不同机器），而非在中间序列偏移处恢复。

字节精确性在**固定确定性配置**下测量：
- `GGML_DETERMINISTIC=1`
- `CUBLAS_WORKSPACE_CONFIG=:4096:8`

在此配置下，同一输入的两次前后紧接的计算本身即字节一致（自比较 KL 精确为 0）。嫁接计算与此零噪声底噪不可区分。字节相等性是单配置、单架构属性——不同架构的 GPU 可能同输入产生不同字节。

### 3.3 唯一数值精确操作点：自身位置嫁接

论文通过直接的对抗性测试证明，**只有自身位置嫁接是字节精确的**。将块重新定位到不同绝对偏移后与新鲜预填充比较，嫁接与新鲜的 KL 约为 0.015，出现少量 argmax 翻转，且在不同偏移量间平坦。

关键对照实验：两个**新鲜**预填充（相同 token，一个在位置 0，一个在位置 $\delta$）之间的 KL 约为 0.014，与嫁接-新鲜差异（0.015）在噪声范围内一致。**嫁接本身未添加任何额外误差**——全部残差来自基础模型自身的浮点位置敏感性。

论文逐一排除了七种候选解释（半精度舍入、滑动窗口缓冲、偏移量级、双旋转路径、频移不匹配、大角度参数缩减误差、物理 slot 放置导致的 reduction-tree 重关联），每种均通过受控测量或零自比较底噪排除。残余的根本原因是：在精确算术中注意力仅依赖相对位置，但在 32 位浮点中同一相对几何以不同绝对角度表达时舍入不同，这个约一个 ULP 的差异经过网络多层和 logit softcap 放大后形成约 0.01 的平坦残余。**这在 32 位浮点中不可约简**。

结论：自身位置嫁接是 32 位 RoPE 编码模型上**唯一可达字节精确数值的制度**，任何引擎都无法在别处达到。论文撤回任何关于字节精确位置组合的表述——经测量后已被撤销。

### 3.4 引擎的输入输出契约

Taliesin 嫁接引擎的实现细节为专有（proprietary），论文仅描述输入输出级别的行为：

**状态捕获接口**：给定模型权重的冻结副本和输入 token 序列，引擎返回捕获的 KV 状态块及其元数据（位置范围、token 计数、配置哈希）。

**状态恢复接口**：给定捕获的 KV 状态块和新的查询 token，引擎在指定位置恢复状态并执行一次前向传递，产生 logit 输出。

**字节精确性验证协议**：在确定性配置下，将恢复的 logit 向量与在相同位置对相同 token 的新鲜计算进行 SHA-256 比较。所有实验均通过此验证。

引擎的内部架构（状态捕获和状态恢复的具体机制、块存储布局、去重和哈希机制）仅在解读测量结果所必需的范围内记录。

### 3.5 块组合与顺序拼接

论文还探索了多个独立捕获的 KV 块的组合使用，并报告了两个明确的制度。**直接并列（stitching）**——将两个独立捕获的最终 KV 状态在上下文中并列放置——失败严重：嫁接与新鲜预填充的 KL 达 13.85，50/50 的 argmax 翻转，因为块 B 在隔离中被预填充且从未注意过块 A（因果饥饿）。**顺序拼接（sequential composition）**——在块 1 解码完成后，在其输出的 token 上铺设块 2，使块 2 逐层关注块 1——功能正确，嫁接与新鲜的分段预填充的中位 KL 降至 0.012，50 个样本中仅 3 个 argmax 翻转。该残余 0.012 与第 3.3 节中识别的 32 位非结合性上限相同（分段 A-then-B 预填充与整体预填充之间的差异），是每个前缀缓存和分块预填充系统固有的，而非此嫁接引擎的特有缺陷。顺序拼接在功能级别正确工作，但针对整体新鲜参考的字节级组合与任何分块预填充系统一样无法实现。

验证顺序拼接的一个关键结果是：full-benchmark 系统配置在 H100 上实现了 100% 的 AIME 系统成绩，证明即使顺序拼接不满足最严格的字节精确标准，在功能层面仍可正确工作。

## 第 4 章 验证知识飞轮（Galahad）

### 4.1 飞轮协议

Galahad 的学习循环设计故意简单：对于冻结模型无法可靠独立求解的问题：

1. **求解（Solve）**：使用额外的推理时间开销求解问题（代码生成 + 链式思考自我验证）
2. **验证（Verify）**：通过外部声音检查确认解的正确性（AIME 问题：执行模型生成的程序并确认输出匹配已知答案；LiveBench：匹配 ground truth）
3. **存入（Deposit）**：将已验证解的 KV 状态作为持久块存储到磁盘
4. **路由（Route）**：对新查询判断其类型，选择相关块
5. **嫁接（Graft）**：将选定块嫁接到当前推理上下文

解仅在通过验证后才进入存储——这是存储可信的来源。

### 4.2 检索的两个制度

飞轮区分两种检索模式，分别测量，从不混淆：

**Recurrence（复发）**：同一问题再次出现。相关块被嫁接，存储的验证答案通过精确查找读取——而不是通过学习分类器。模型不重新推导任何东西。这是成本故事。

**Transfer（迁移）**：出现同结构的新问题（AIME 变体：数字常量被替换并独立重新验证；LiveBench：时间上 hold-out 的 split，零问题 ID 重叠）。一次性分类选择相关块，嫁接后冻结模型**自适应**缓存方法到新实例。这是能力故事——测试泛化而非记忆。

### 4.3 路由 vs 扁平合并

早期设计尝试将所有缓存方法放入单个扁平前缀。结果发现这会将模型混淆——当多个条目同时存在时，模型抓取错误的条目（召回 5/8，一个查询返回了另一问题的答案）。修正方案将每个已验证解存储为独立块，**按查询路由到唯一相关块**，仅嫁接该块。路由而非扁平合并是最终报告系统的版本。

路由器的具体实现基于块内容的类型签名（type signature）而非语义嵌入。每个块记录其解决的问题类型、输入参数结构和验证哈希。新查询通过与这些类型签名进行匹配来选择块——这是一次性分类操作，不需要额外的模型推理。路由器在无法确定时选择放弃（abstention）而非返回错误答案，这一设计决定了系统的行为退化特性（graceful degradation）。

### 4.4 飞轮的存储与生命周期

已验证解存入磁盘后成为持久 KV 块。块的生命周期包括：

1. **存入（Deposit）**：问题通过额外推理求解后，经过外部声音验证（代码执行确认），将求解过程的 KV 状态写入磁盘。存入是一次性操作。
2. **存储（Store）**：KV 块作为普通二进制文件存储在磁盘上，不占用任何加速器内存。AIME 2025 全部 8 个问题的验证库约 4,571 token，捕获为 441 MB KV 状态。
3. **检索（Retrieval）**：查询到达时，路由器确定类型后读取对应 KV 块并从磁盘加载。块加载后嫁接到推理上下文——从磁盘加载到部署完成约 0.29 s。
4. **嫁接（Graft）**：块在其原始捕获位置恢复，解码新查询的 token。整个过程不改变模型权重，不消耗额外的加速器内存。

关键区别：存入是一次性计算开销（约 723 s 构建 2.85M token 存储），之后所有查询都只支付嫁接的成本（约 0.29 s + 新 token 解码）。这与传统 RAG 每次查询都重新计算整段上下文的模式有本质区别。

| Argmax 不一致数 | 0 / 50 |
| 嫁接失败数 | 0 / 50 |
| Mann-Whitney p | 1.0000 |

在 Gemma-4-12B GPU 上，所有 50 样本的 `bench_logit_kl` 返回零嫁接失败、零 argmax 不一致，SHA 字节相等性测试每次通过。跨上下文嫁接同样通过：在一个上下文中捕获的状态恢复到一个独立创建的新上下文后，复现了预期的 logit。完整企业测试套件报告 15/15 测试通过（含后端身份、版本隔离、哈希一致性、并发性检查）。

### 5.3 成本引擎：85.6x 预填充补贴

| 路径 | 预填充工作 | 时间 |
|------|-----------|------|
| 冷（新鲜完整预填充） | 11,994 prompt token | 1,547.3 ms |
| 热（嫁接，KV 复用） | 1 prompt token | 18.1 ms |
| **加速比** | | **85.6x** |

滑动窗口注意力的修复需求值得一提：该模型是滑动窗口注意力模型，原生提示缓存仅从稀疏检查点恢复；启用全尺寸 KV（64K 上下文下 19.7-25.5 GB）后恢复精确恢复。此外多 slot 服务器上未固定的请求循环调度到冷 slot，固定缓存承载调用到其 slot 后解决。两项修复后，5,569 token 新鲜前缀从 1,087 ms 冷降低至 13 ms 热（83.7x）。

这两项修复本身就值得记录，因为它们代表了"假装精确缓存"和"真正精确缓存"之间容易被忽视的工程差距。许多生产系统声称已实现 KV 缓存复用，但在滑动窗口和调度细节上取了捷径，导致实际加速比低于理论值。

### 5.4 31B LiveBench 结果

论文在 31B 模型上使用 LiveBench 进行了额外评估。LiveBench 对模型的挑战不同于 AIME：每个块包含多个示例（multi-exemplar），而非 AIME 的单解块。结果是复发效果显著减弱：

- 对于 AIME 风格的单个解块：复发 8/8，所有问题被优雅解决
- 对于 LiveBench 的多示例块：复发仅 5/20，模型倾向于"重新解决"而非"读取缓存"

这表明块的结构设计对复发效果有根本性的影响。当单个块封装多个示例时，模型更容易忽略缓存的答案而重新进行推理。这是一个已测量的局限性而非缓存机制故障。

### 5.5 关于能耗测量的仪器限制

论文诚实记录了能耗测量的一个系统限制：在 0.5-2 Hz 的功率采样率下，一个 2.8 s 的运行接近采样器的分辨率极限。因此，能耗数字有两种解读方式：

- **积分值**（基于每次采样的瞬时功率积分）：0.053 Wh，对应约 8,700 倍能耗减少
- **保守边界**（平均采样功率 × 墙钟时间）：0.145 Wh，对应约 3,000 倍能耗减少

论文报告了两个数字的区间（约 3,000–8,700 倍），而非一个点。重要的是，即使在保守边界下，能耗减少仍然超过三个数量级——这一量级的确定性不依赖于一个或另一个端点的确切值。

### 5.6 上下文窗口 87 倍扩展

构建包含 2,854,766 token 的存储（88 个持久块），每个块携带唯一的 planted "needle"。从覆盖整个深度的块中读取 needle：

| 属性 | 测量值 |
|------|--------|
| 存储大小 | 2,854,766 token（87.1x 配置的 32,768 token 服务窗口），磁盘 40.6 GB |
| 额外加速器内存 | 0（slot 保持 32K，峰值 25,595 MB，等于基础服务） |
| 检索 | 7/7 needle 在深度 0/334K/694K/1.41M/2.13M/2.49M/2.82M 处正确读取 |
| 访问成本 | 恢复 0.29 s + ~35 个新 token 预填充；复杂度恒定，不随深度增长 |
| 存入 | 723 s 一次性，然后永久在磁盘上 |

负控制确保了测量的诚实：窗口停靠第一个块时，查询最后一个块的 needle 返回错误数字——窗口确实移动到数据所在位置，并未秘密持有 2.8M token 在活注意力中（硬件也无法做到）。原生 2.85M token 上下文需要远超 32 GB 显卡的 KV 内存，且每次调用重新预填充到该深度的时间与深度线性增长。此处 2.85M 存储在磁盘上，任意点通过一次约 0.29 s 的嫁接即可到达。**32K 扩展到 2.85M 的代价是一次线性存入、40.6 GB 磁盘，零额外加速器内存和随窗口扩展的每次访问代价。**

### 5.7 飞轮使 12B 更智能：80.0% → 93.3%

AIME 2025（2025 年 2 月发布的 30 道竞赛题，晚于模型 2025 年 1 月的训练截止日期）：

冻结 Gemma-4-12B 使用自身最佳推理配置（路由链式思考自我验证和可靠代码执行）达 80.0%（24/30）。此配置的置信门控下，22 道自信求解，剩余 8 道（#9, #10, #11, #13, #14, #20, #28, #30）标记为不确定——这 8 道包含所有 6 道完全失败的题和 2 道无置信度解出的题。

飞轮针对这组失败集合。每道题通过额外计算和**代码验证**（生成程序执行后输出已知答案）求解，产生 8 条验证库（约 4,571 token），捕获为 441 MB KV 状态。嫁接库后呈现全部 8 个目标：

| 目标问题 | 库结果 |
|---------|--------|
| #9, #10, #13, #20, #28, #30 | 解决（62, 81, 204, 336, 248, 240） |
| #11, #14 | 未解决 |
| **系统得分** | 22（冻结 12B 自信正确）+ 6（库）= **28/30 = 93.3%** |

冻结 Gemma-4-12B 裸模型：80.0%。+ 嫁接验证库：**93.3%**。13 个百分点的提升是学习到的缓存状态的价值——使 12B 解决了它真正无法解决的问题，超越自己的厂商锚定值（77.5%）和 31B 的厂商锚定值（89.2%）。

不同配置的对比：

| 配置（相同硬件，30 道题） | AIME 分数 | 解码 token/题 |
|---------------------------|----------|--------------|
| 冻结 12B 裸模型（pass@1） | 56.7% | ~3,300 |
| 采样投票阶梯 | 76.7% | ~25,000 |
| 轻量代码路由，无缓存知识 | 76.7% | ~4,100 |
| 代码路由 + 嫁接验证库 | **90.0%** | ~4,360 |

加入缓存验证知识后，分数从 76.7% 提升至 90.0%，仅增加约 5.6% 的 token 开销。从缓存验证知识购买能力的成本每百分点约便宜 50 倍。

### 5.8 飞轮使 12B 更便宜：6,574x 更少 token

复发场景（同一 8 道题，嫁接块，读取验证答案）：

| 指标 | 数值 |
|------|------|
| 得分 | 8/8（含 #28，之前盲点） |
| 解码 token | 61 总（7.6/题） |
| 基础 best-of-5 对比 | 401,026 token，解决 0/8 |
| 墙钟时间 | 2.8 s |
| 能耗 | 0.053 Wh 积分 |

基础模型在 401,026 token 的 best-of-five 预算下，未能解决这 8 道题中的任何一道。冻结模型 + 持久化解状态在 61 个解码 token 内全部解决，在四次独立运行中均可复现。这就是"一次求解，不再重付"的直接算术。

### 5.9 迁移：同一存储泛化到新数据

给定 7 个独立验证的同结构变体（常量交换，每答案三重交叉校验），冻结 12B 路由到类型块、嫁接、自适应缓存程序到新数字并执行：

- 得分：**5/7**（#9, #13, #14, #20, #30 在所有 5 个样本上正确；确定性复制）
- 路由：7/7
- 失误：#28 过度自适应了一个结构常量（range(4)→range(2024)），引入精确分数爆炸；#11 缓存代码硬编码 sqrt(185)，变体需要 sqrt(697) 无法通过数字替换迁移

31B 在 H100 上的迁移：**7/7 hold-out 迁移通过**，缓存代码完全来自 12B 的解，跨规模零修改。

除了 RTX 5090（Blackwell 消费级）上的全面测试，论文还在两个额外 GPU 架构上验证了核心结果：

**B200（Blackwell 数据中心级）**：通过预注册 replay 验证了字节精确性的跨架构可移植性。预注册论文提交前提交了源码树哈希、pass criteria 和可证伪预测，执行后所有条件满足。

### 5.11 路由精度与退化行为

路由器在不同配置下的行为被单独测量。对于 12B 的 8 个 AIME 复发查询，路由正确率 8/8。路由器在无法确定时选择放弃（abstention）而非返回错误答案。在更复杂的 multi-exemplar LiveBench 设置中，路由器的置信区间被报告而非单点估计，反映了块选择不确定性的真实分布。

关键设计决策：路由器和嫁接答案之间没有置信门控——"自信错误"的嫁接在结构上是可能的，尽管在测试样本量下未观察到。

### 5.12 工程技能手册演示

除了 AIME 和 LiveBench 基准测试，论文还提供了一个工程场景的端到端演示。一个 464 token 的技能手册（skill manual）被捕获为 160 MB 的计算 KV 状态，写入磁盘后恢复字节精确。此后，模型使用仅缓存的 skill 手册成功路由 6/6 个任务到正确技能。

这一演示展示了飞轮的实用价值：将已验证的工程知识（如 API 使用方法、调试技巧、配置流程）以 KV 块形式持久化，后续查询可以零误差恢复。原生内存内缓存无法将状态持久化到磁盘并恢复到新进程中；而字节精确的磁盘块可以（块大小因服务配置不同而不同，不同章节间的块大小不与 token 数线性相关，论文对此有详细说明）。

## 第 6 章 方法学分析与设计讨论

### 6.1 能力的购买经济学

标准方式购买一个百分点的基准准确率：花更多——更多参数、更多训练、更多推理采样。论文在相同硬件和相同问题上给出了替代方案的价格：

| 方法 | AIME 分数 | Token/题 | 性价比 |
|------|----------|---------|--------|
| 采样投票 | 76.7% | 25,000 | 基准 |
| 缓存验证知识 | 90.0% | 4,360 | **~50x 便宜每百分点** |

原因在于结构差异。采样在其每次查询上都全额付费，永久如此；验证存入支付一次性成本后仅收取嫁接费用。失败的问题是昂贵的（10.6-13.5K token vs 2-3K token），因此飞轮的"一次求解，不再重付"精准攻击了占主导地位的成本。

这一结构优势在基准规模变大时更加显著：一个采样投票系统需要在每次问题出现时重新推理，而飞轮系统只需在第一次求解时支付完整成本，后续每次查询仅支付嫁接成本（约 18 ms + 新 token 解码）。对于频繁出现的问题（如标准库函数、常见数学题解），这种优势可以无限放大。

### 6.2 大模型并不总是更便宜

论文创造了一个反转直觉的发现：一个大型 MoE 模型在相同问题上生成了 2.44M token（对比 12B 的 768K token），仍无法在预算内完成一半尝试。**大模型的每 token 廉价被啰嗦消耗所吞噬，每求解问题的计算开销与 12B 持平。** "大模型，便宜 token"在固定内存预算下的硬推理中并不成立。

具体来看：在同一组 AIME 问题上，冻结 12B 模型使用自己的最佳推理配置（72K token 解码、约 18K token 预填充），而大 MoE 模型由于需要更多 token 来表达其思考过程和自我验证，总解码量大幅增加。尽管 MoE 的每 token 计算成本可能更低（稀疏激活），但绝对解码量增长更快，导致每求解问题的总计算量基本相当甚至更高。

### 6.3 复现性与审计边界

由于引擎为专有（proprietary），论文在复现性方面采用了"承诺输入→哈希输出→独立可查得分"的验证架构：

1. 每次运行前，输入（数据集和 runner 脚本）的 SHA-256 哈希被提交
2. 每次运行后，输出（结果 JSON、原始逐题生成）的哈希在退出时被记录
3. 结果文件包含原始模型生成和每道题的求解代码，读者可独立重新运行求解代码并重新检查评分
4. 跨架构 replay 额外预注册了源码树哈希、pass criteria 和可证伪预测（在运行前提交）
5. 字节精确性测量报告了构建版本和确定性配置（GGML_DETERMINISTIC=1, CUBLAS_WORKSPACE_CONFIG=:4096:8）

**不需要专有引擎来验证论文报告的分数是否诚实**。引擎仅在重新生成输出时需要；验证报告数字的诚实性不需要它。

### 6.4 精确性买什么

整个构建依赖于第 4.1 节的字节精确性。如果嫁接只是新鲜状态的近似，能力结果将被混淆（是模型更智能了，还是近似正在向答案漂移？），复发结果也不可信（缓存答案能无损往返吗？）。字节相等性同时消除这两个疑问。嫁接状态 = 模型已阅读该知识，因此存入可以作为学习单位。

位置约束不是论文强加的限制，而是 32 位浮点 RoPE 编码下问题的形状——任何引擎都无法在此模型上实现位置重新定位的字节精确性。论文通过对抗性测试主动发现并证明了这一点，而非通过假设排除。

### 6.5 与现有方法的关系

Taliesin/Galahad 方法填补了现有 KV 状态复用方法中的一个空白：它同时满足了"精确"和"持久"两个条件。与其他方法的对比关系：

- **对比前缀缓存**：前缀缓存精确但短暂（服务进程重启后丢失）；Taliesin 是精确且持久的。
- **对比CacheGen等压缩方法**：这些方法通过有损压缩实现持久化，但恢复后的状态不是字节精确的；Taliesin 不做任何压缩，保持字节精确。
- **对比RAG**：RAG 注入外部知识为文本 token，每次读取都重新计算注意力；Taliesin 注入知识为 KV 状态，嫁接后无需重新计算。
- **对比FCGRAFT**：两者都使用"嫁接"一词，但 FCGRAFT 的嫁接是宏级别、功能级别的——它缓存和改进代码骨架函数的 KV 状态，但不提供字节精确保证。Talisien 的嫁接是字节精确的。

## 第 7 章 局限性与未来展望

### 7.1 已知局限

论文诚实列出了多个边界：

- **迁移的可靠性边界**：迁移仅当缓存程序**在变化量上是参数化的**时才可靠。特定问题硬编码的常量（如 sqrt(185) 而非 sqrt(N)）迫使重新推导，可能失败。论文中 12B 在 #11 和 #28 上的失败即源于此——#28 中模型过度自适应了一个结构常量（range(4)→range(2024)），引入了精确分数爆炸。
- **复发强度差异**：复发对单解块（single-solution blocks）极为廉价（AIME：8/8）；对复杂的多示例块（multi-exemplar blocks）则较弱（LiveBench：31B 倾向重新解决而非读取缓存）。
- **饱和**：飞轮在模型已经表现良好的问题上无效果。如果模型已经在某个问题上达到 97-100% 的准确率，缓存验证知识不会进一步改善——它只是没有发挥作用的对象。
- **缓存过程可能有害**：如果缓存过程重新推荐了模型自身已经以更高默认性能执行的方法，可能产生负效果。论文指出，飞轮在不发生模型失败的地方不起作用（饱和），且缓存的过程如果错误地重新推荐了一个模型已经以更好默认方式执行的方法，可能是主动有害的。
- **跨架构限制**：字节精确性是单架构、单配置属性。不同 GPU 架构之间字节精确性不保证。RTX 5090 上捕获的块在 H100 上不是字节精确的——尽管嫁接操作在每种架构上本身是字节精确的。
- **路由器置信缺口**：路由器和嫁接答案之间没有置信门控，因此"自信错误"的嫁接在结构上是可能的（尽管在当前样本量下未观察到）。
- **LiveBench 复发较弱**：对于多示例 LiveBench 块，31B 倾向于重新解决而非读取缓存答案（复发 5/20）。这与 AIME 的单个解块（8/8 复发）形成对比，说明块结构设计对复发效果有重要影响。
- **磁盘分页的单节点限制**：分页测量在单节点上完成，不携带高并发声明。
- **位置偏移不可字节精确**：第 3.2 节已建立，自身位置嫁接是 32 位浮点 RoPE 模型上引擎可以达到的唯一字节精确数值操作点。
- **100% 和 93.3% 是飞轮系统数字**：其中核心泛化组件是 hold-out 迁移（31B 上 7/7，12B 上 5/7）。论文在整个报告中小心地将系统数字与泛化数字区分开来。

### 7.2 适用边界

论文给出清晰的适用条件：**缓存模型缺失的已验证知识，路由而非合并，自身位置嫁接，仅在缓存程序是参数化时信任迁移。**

### 7.3 经济意义

对于已将每一缺口都通过更多规模来回答的领域，论文提供了直截了当的可测量替代方案：以精确状态添加已验证知识是廉价的，检索它远比大模型从头重算便宜，而且两者都不触碰权重。

### 7.4 未来方向

论文指出两个系统问题已获测量答案但留有优化空间：路由错误时通过放弃（abstention）优雅降级而非默认错误；磁盘分页（disk paging）扩大了而非侵蚀了预填充补贴。未来工作可探索多块组合的更鲁棒方案、跨架构字节精确性的实现路径、以及将飞轮应用于更广泛的任务类型。
