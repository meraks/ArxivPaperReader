## 1.2 核心问题与动机

大语言模型 Agent 在执行长程任务（long-horizon tasks）时，需要在多轮工具调用和环境交互中维持对任务需求、环境状态、失败诊断、中间发现和未完成子目标的追踪。然而随着轨迹增长，这些本应指导后续决策的信息——即使仍存在于上下文窗口中——也常常停止对 Agent 行为产生有效影响。本文将这一失败模式定义为 **behavioral state decay（行为状态衰减）**。

现有的记忆系统主要关注存储、更新和检索相关记录（MemGPT、MemoryBank、Generative Agents 等），这对个性化、持久化和跨会话记忆至关重要。但长程任务执行提出了不同的问题：记忆不仅要能「存」和「取」，还要决定「何时」干预。过少的记忆让 Agent 重复错误；过多的记忆增加延迟、消耗 token，并可能分散注意。

## 1.3 五大贡献

1. **定义行为状态衰减**：形式化描述了长程 Agent 在执行过程中决策相关信息停止影响行为的失败模式。
2. **提出记忆干预架构**：一个独立的记忆 Agent 与未修改的动作 Agent 并行运行，在固定间隔更新结构化记忆库并决定是否注入提醒。
3. **系统性的实验验证**：在 Terminal-Bench 2.0 和 τ²-Bench 上验证，记忆干预持续提升长程任务完成率。
4. **完整的消融实验**：选择性干预优于被动记忆暴露、始终注入、顾问模式和通用检索。
5. **开源模型初步探索**：在 Qwen3.5-27B 上通过 SFT + GRPO 训练记忆策略，验证了干预策略的可学习性。

## 1.4 关键结果速览

| Opus 4.6 | 无（基线） | 43.5% | 66.2% |

| Qwen3.5-122B-A10B | 训练 Qwen3.5-27B 记忆 | **41.1%（+3.5pp）** | — |

# 第 2 章 研究背景与动机

## 2.1 长程语言 Agent

语言模型 Agent 通常被实例化为交错的推理-动作（reasoning-and-acting）系统，在多个步骤中发出工具调用、观察环境反馈并修正计划。近年来的基准测试将这一设定推向现实的长程任务：命令行执行（Terminal-Bench）、工具-Agent-用户交互（τ²-Bench）、机器学习工程（MLE-bench）等。

这些场景暴露了单轮推理基准无法捕捉的失败模式：Agent 可能重复已失败的 action、丢失对任务需求的追踪、或偏离早期发现的信息。即使上下文窗口足够容纳完整的轨迹历史，模型对历史信息的利用也受限于信息在上下文中的位置（Liu et al., 2024）。

## 2.2 现有记忆系统的不足

现有的 Agent 记忆系统（MemGPT、MemoryBank、Generative Agents、Mem0）主要优化三个能力：

1. **存储**：将经验编码为自然语言记录。
2. **更新**：随时间修正或补充已有记录。
3. **检索**：在需要时找到相关记忆。

但长程任务执行提出了第四个能力：**干预决策（intervention）**。记忆不仅要被检索到，还要决定是否应主动注入到 Agent 的下一次决策循环中。现有系统缺乏这一「何时保持沉默、何时打断」的校准能力。

## 2.3 相关方向对比

**反思与自改进**：Reflexion 将前序尝试的文本反思存入 episodic memory buffer 供后续参考；Self-Refine 使用自生成的反馈迭代改进输出。这些方法需要修改动作 Agent，且反思和行动的耦合较紧。

**顾问模型**：Advisor 方法使用第二模型向黑盒执行模型提供自然语言指导。记忆 Agent 与之相关但更受约束：它不提供广泛的战略建议，而是从维护的执行状态中提取基于记忆的提醒。

**上下文管理**：Memory-as-Action 将工作记忆管理建模为显式的编辑操作；Context-Folding 允许 Agent 将子轨迹折叠为摘要。本文与之互补，但使用独立 Agent 而非训练动作 Agent 来管理上下文。

# 第 3 章 记忆干预架构

## 3.1 总体设计

本文的核心设计是**分离记忆维护与动作选择**。一个独立的记忆 Agent（$$\pi_M$$）与未修改的动作 Agent（$$\pi_A$$）并行运行。记忆 Agent 在第一步和每隔固定步数被调用。在每个记忆时间步 $$t$$，它：

1. 观察任务描述、最近的轨迹窗口 $$w_t$$ 和当前记忆库 $$B_{t-1}$$
2. **Phase 1 — 更新记忆库**：根据最新轨迹信息，对记忆库进行增、删、改操作
3. **Phase 2 — 干预决策**：决定是否向动作 Agent 注入一条基于记忆的提醒，或保持沉默

干预的输出是一条简短的文本提醒（text reminder），被注入到下一次动作 Agent 调用的上下文中，作为瞬态记忆上下文（transient memory context）。

## 3.2 记忆库结构

记忆库 $$B_t = (s_t, K_t, P_t)$$ 包含三个部分：

| 组件 | 符号 | 内容 | 是否暴露给动作 Agent |
|------|------|------|-------------------|
| **状态字段（Status）** | $$s_t$$ | 记忆 Agent 私有的进展视图、未解决问题、未解决风险 | ❌ 私有 |
| **知识记忆（Knowledge）** | $$K_t$$ | 相对稳定的事实：任务需求、环境属性、文件路径、已验证的事实 | ✅ 可选择暴露 |
| **程序记忆（Procedural）** | $$P_t$$ | 尝试与结果：已失败的命令、已成功的修复、被排除的假设、诊断信号 | ✅ 可选择暴露 |

每条记忆条目包含短标识符、自然语言内容和元数据（创建时间、访问统计）。标识符允许记忆 Agent 显式更新或删除过时条目。格式采用紧凑的带标签文本，例如 `[ENV]` 标识环境事实、`[PATH]` 标识路径、`[BUG]` 标识 bug。

## 3.3 两阶段工作流

**Phase 1 — 记忆库编辑（Memory Edit）**：

$$B_t \sim \pi_M^{\text{edit}}(\cdot \mid x, w_t, B_{t-1})$$

记忆 Agent 根据最新的轨迹信息和已有的记忆库，决定：
- 添加新条目（新发现、新失败、新事实）
- 更新已有条目（修正、补充）
- 删除过时的条目

**Phase 2 — 干预决策（Intervention Decision）**：

$$i_t \sim \pi_M^{\text{intervene}}(\cdot \mid x, w_t, B_t)$$

记忆 Agent 决定是否发出干预，其中 $$i_t \in \{\varnothing, \text{text reminder}\}$$。非空的干预被注入到下一次动作 Agent 调用中；空干预则动作 Agent 在无额外记忆上下文的情况下继续执行。

**关键设计原则**：状态字段 $$s_t$$ 始终私有，不向动作 Agent 暴露。这保证了记忆 Agent 可以维护一个关于任务进展的内部工作模型，而不会污染动作 Agent 的上下文。

## 3.4 PLug-and-Play 整合

该方法的关键优势是与现有 Agent 系统的兼容性：
- **动作 Agent 无需修改**：任何现有的 ReAct 风格 Agent 都可以直接配合使用
- **现有 Agent 框架兼容**：可与 LangChain、CrewAI、AutoGen 等框架集成
- **开销可控**：记忆 Agent 仅在固定间隔被调用，不是每步都运行

# 第 4 章 实验结果与分析

## 4.1 实验设置

**基准测试**：

| 基准 | 描述 | 评估指标 |
|------|------|---------|
| **Terminal-Bench 2.0** | 自主命令行执行任务 | Pass@1 |
| **τ²-Bench** | 交互式工具使用 + 领域规则遵守 | Pass@1 |

**动作 Agent**：
- Claude Sonnet 4.5（中端）
- Claude Opus 4.6（前端）
- Qwen3.5-122B-A10B（开源）

**记忆 Agent**：
- Claude Opus 4.6（提示驱动）
- Qwen3.5-27B（SFT + GRPO 训练）

## 4.2 主实验结果

| 动作 Agent | 记忆配置 | Terminal-Bench 2.0 | τ²-Bench |
|-----------|---------|-------------------|----------|
| Sonnet 4.5 | 无记忆 | 37.6% | 55.0% |
| Sonnet 4.5 | + Opus 4.6 记忆 | **45.9%（+8.3pp）** | **61.8%（+6.8pp）** |
| Opus 4.6 | 无记忆 | 43.5% | 66.2% |
| Opus 4.6 | + Opus 4.6 记忆 | **45.9%（+2.4pp）** | **68.7%（+2.5pp）** |

**关键发现**：
1. **记忆干预对弱动作 Agent 提升更大**：Sonnet 4.5 获得了 +8.3pp 和 +6.8pp 的提升，而 Opus 4.6 的提升为 +2.4pp 和 +2.5pp。这表明强 Agent 本身已具有一定程度的状态维持能力，但记忆干预仍能带来增益。
2. **增益不会随 Agent 能力增强而消失**：即使是前端模型 Opus 4.6，记忆干预仍稳定带来 +2+pp 的提升。

## 4.3 消融实验

为了理解各种设计选择的影响，作者进行了系统的消融实验：

| 消融条件 | 实验设置 | 相对性能 |
|---------|---------|---------|
| **选择性干预（本文方法）** | 记忆 Agent 维护记忆库并选择性注入 | **最佳** |
| 被动记忆暴露 | 创建完整记忆摘要但始终暴露给动作 Agent | 降低性能 |
| 始终注入 | 每步都注入记忆提醒 | 降低性能 |
| 顾问模式 | 记忆 Agent 提供广泛战略指导而非约束性提醒 | 降低性能 |
| 通用检索 | 标准 RAG 检索（无结构化记忆库） | 降低性能 |

**核心结论**：选择性干预优于所有对照方案。过多的记忆注入会分散 Agent 注意力，而纯被动暴露则让 Agent 难以区分重要和无关信息。

## 4.4 定性分析

成功的干预通常具有三个特征：
- **具体性（Specific）**：提醒针对明确的失败原因或未完成的需求，而非泛泛的建议
- **基于记忆（Grounded）**：提醒源于记忆库中已验证的执行状态，而非推测
- **时机适当（Timely）**：在 Agent 即将做出错误决策前注入

失败的干预主要是校准误差（calibration errors），而非记忆存储失败。偶尔，记忆 Agent 会以过高置信度提出推测性推断、重复 Agent 已知的信息，或引发不必要的验证。

# 第 5 章 开源模型训练与分析

## 5.1 训练设置

作为向开源记忆策略迈出的初步一步，作者在 Qwen3.5-27B 上训练记忆 Agent，同时保持 Qwen3.5-122B-A10B 动作 Agent 冻结。

**训练数据**：SETA（可执行终端 Agent 任务的集合，带验签器奖励）。SETA 用于监督微调和强化学习，Terminal-Bench 2.0 作为留出测试集以评估迁移能力。

## 5.2 SFT 训练

SFT 蒸馏提示驱动记忆轨迹，同时监督：
- **Phase 1 记忆库操作**：记忆条目的添加、更新、删除
- **Phase 2 干预决策**：是否在当前时间步注入提醒

## 5.3 GRPO 训练

GRPO 进一步优化干预校准。由于任务级验签器奖励在多次记忆调用上是稀疏的，训练更新聚焦于**枢轴轮次（pivot turns）**——通过标签化离线 rollout 识别出那些最可能影响下游任务成功与否的内存决策点。

## 5.4 训练结果

| 训练设置 | 平均奖励 | 解决数 | 相对基线变化 |
|---------|---------|-------|------------|
| 无记忆（基线） | 0.709 | 56 | — |
| + Qwen3.5-27B base（未训练） | 0.693 | 54 | **-0.016** ❌ |
| + SFT 记忆 | 0.720 | 58 | **+0.011** ✅ |
| + GRPO 记忆 | **0.734** | 58 | **+0.025** ✅ |

| 设置 | n | Terminal-Bench Pass@1 | 变化 |
|------|---|---------------------|------|
| Qwen3.5-122B-A10B 动作 Agent 仅 | 85 | 37.6% | — |
| + 训练的 Qwen3.5-27B 记忆 | 85 | **41.1%** | **+3.5pp** |

**关键发现**：
1. **未训练的 27B 记忆 Agent 有害**：将未训练的 27B 模型作为记忆 Agent 会降低性能（0.709→0.693），说明记忆策略需要精心校准。
2. **SFT 恢复并超越基线**：SFT 不仅恢复了未训练模型的损失，还带来了 +0.011 的奖励提升。
3. **GRPO 进一步提升校准**：GRPO 优化了「何时沉默 vs 何时干预」的决策边界，将奖励提升至 0.734。
4. **迁移有效**：SETA 训练的模型在留出的 Terminal-Bench 2.0 上取得了 +3.5pp 的提升，表明学到的记忆干预策略具有一定泛化能力。

# 第 6 章 局限性与展望

## 6.1 当前局限

**固定间隔调用**：记忆 Agent 在固定步数间隔被调用，而非自适应触发。更高效的方案应让记忆 Agent 仅在必要时激活，减少不必要的计算。

**干预校准仍不完美**：定性分析显示，记忆 Agent 仍会犯以下错误：
- 以过高置信度提出推测性推断
- 重复动作 Agent 已知的信息
- 引发不必要的验证，浪费 token 和延迟

**代码未发布**：截至报告撰写时，GitHub 仓库仍为空占位符，无法验证实现细节或进行复现。

**单一动作 Agent 架构**：实验仅覆盖了 ReAct 风格 Agent，未验证是否适用于其他 Agent 架构（如 Tree-of-Thoughts、Plan-and-Solve）。

## 6.2 开放方向

**端到端联合训练**：本工作冻结了动作 Agent。未来可探索记忆 Agent 和动作 Agent 的联合训练，让两者共享语义空间的同时保持职责分离。

**自适应调度**：让记忆 Agent 自己决定何时被调用（而非固定间隔），在任务状态稳定时静默、在出现关键状态变化时主动介入。

**提醒形式的优化**：当前提醒是文本形式的记忆条目。未来可探索不同形式的记忆注入——摘要 vs 逐字提醒、抽象 vs 具体——在不同任务类型中的效果差异。

**跨 Agent 迁移**：训练好的记忆策略能否在不同动作 Agent 之间迁移？能否在商业模型之间泛化？这是实用的关键问题。

**安全与鲁棒性**：记忆 Agent 可能被用来注入误导信息或压制有效的探索行为。需要研究记忆干预的安全边界和鲁棒性保证。

## 6.3 总结

本文提出了记忆作为主动干预机制而非被动存储的新视角。通过独立记忆 Agent 的两阶段架构——结构化记忆库维护 + 选择性干预决策——在两项长程 Agent 基准上持续提升了任务完成率。初步的开源模型训练实验表明，干预策略是可学习的。这项工作为 Agent 记忆系统的设计提供了一个新的维度：不仅考虑「记得什么」，更要考虑「何时介入」。
