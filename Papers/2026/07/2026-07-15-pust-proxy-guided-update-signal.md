## 第 1 章 概述

### 一句话核心 claim

PUST（Proxy-guided Update Signal Transfer）将 LLM 后训练中的策略探索（exploration）与分布对齐（alignment）解耦：用一个轻量代理模型（proxy）完成高成本的探索，提取其优化前后的相对改进信号，再将该信号转移到主模型上引导对齐。这使得探索结果可异步生成、缓存、跨模型复用，并天然支持弱到强（weak-to-strong）的提升。

## 第 2 章 研究背景与动机

### 2.1 后训练的两阶段解构

LLM 后训练当前主流方法可分为两类：

- **奖励优化**（PPO、GRPO 等）：通过在线 rollout + 奖励反馈主动探索高奖励行为。探索能力强，但计算成本高，且需在多域依次串行优化。
- **分布匹配**（OPD 等）：将学生模型的分布对齐到已优化的专家教师分布。对齐效率极高（约 20 步即可收敛），但本身不产生探索信号，须依赖外部教师。

### 2.2 GRPO vs OPD 的实证对比

论文在 Qwen3-1.7B 上系统对比了 GRPO 与 OPD 的差异：

1. **收敛效率**：所有 OPD 变体约 20 步即快速收敛，而 GRPO 需要大量的探索阶段才能找到有效更新方向。
2. **最终效果**：GRPO 和 OPD 最终收敛到可比水平。
3. **OPD 的奖励盲区**：即使加入 OPD FT（丢弃完全正确的轨迹组）和 OPD URM（基于 reward 的 token 级 mask），最终效果变化不大，说明 OPD 本质上是奖励不可知的——只是机械地匹配教师分布。

关键发现：策略改善的真正方向信号（directional signal）来自奖励优化中的主动探索，而非分布匹配本身。因此，将探索与对齐解耦、使探索信号可复用和跨模型迁移，是提升后训练效率的关键方向。

## 第 3 章 核心技术：PUST 框架

PUST 将后训练拆解为三个独立阶段：

### 3.1 阶段一：代理探索（Proxy Exploration）

**核心思想**：不在主模型上直接做高成本的 reward optimization，而是部署一个轻量级代理模型 $\pi_{\phi}$，对其进行标准的 GRPO/PPO 优化，得到优化后策略 $\pi_{\phi}^{+}$。

优势：
- 探索成本大幅降低（代理模型参数可小至主模型的 1/5）
- 可并行部署多个代理模型，同时探索不同 reward 分布下的最优行为
- 主模型仅需接收探索结果，免于反复采样和 reward 计算

### 3.2 阶段二：更新信号提取（Update-Signal Extraction）

从代理模型的策略变化中提取相对改进信号，而非直接蒸馏其绝对分布：

$$\Delta_{\phi}(a \mid s_t) = \log \pi_{\phi}^{+}(a \mid s_t) - \log \pi_{\phi}(a \mid s_t) = \log \frac{\pi_{\phi}^{+}(a \mid s_t)}{\pi_{\phi}(a \mid s_t)}$$

其中 $\Delta_{\phi} > 0$ 表示代理模型在状态 $s_t$ 下选择 token $a$ 的倾向被 reward 鼓励增强，$\Delta_{\phi} < 0$ 表示被抑制。

该相对信号是广义的方向性改进指示，与代理模型的绝对能力无关，因此天然可跨模型迁移。

### 3.3 阶段三：信号迁移（Signal Transfer）

将提取的更新信号迁移到主模型 $\pi_{\theta}$ 上。为避免静态信号的过更新（over-updating），引入锚定校准机制：

$$\Delta_{\theta}(a \mid s_t) = \log \frac{\pi_{\theta}(a \mid s_t)}{\pi_{\text{ref}}(a \mid s_t)}$$

定义经过锚定校准的 token 级迁移效用：

$$r_{\lambda}(a \mid s_t) = \Delta_{\phi}(a \mid s_t) - \lambda \Delta_{\theta}(a \mid s_t)$$

其中 $\lambda > 0$ 为校准系数，控制迁移保守度。$\lambda$ 越小，主模型越激进地跟随代理方向；$\lambda$ 越大，越严格约束其不偏离锚点。

最终优化目标：

$$\mathcal{L}_{\text{proxy}}(\theta) = -\mathbb{E}_{s_t \sim \mathcal{D}} \left[ \sum_{a \in \mathcal{V}} \pi_{\theta}(a \mid s_t) \left( \log \frac{\pi_{\phi}^{+}(a \mid s_t)}{\pi_{\phi}(a \mid s_t)} - \lambda \log \frac{\pi_{\theta}(a \mid s_t)}{\pi_{\text{ref}}(a \mid s_t)} \right) \right]$$

该目标等价于最小化主策略与动态诱导目标分布之间的 KL 散度。

## 第 5 章 实验结果与分析

### 5.1 PUST 主结果（Q1）

| 模型配置 | AIME 24 | AIME 25 | HMMT 25 (Feb) | HMMT 25 (Nov) | 平均 |
|----------|:-------:|:-------:|:-------------:|:-------------:|:----:|
| Qwen3-1.7B Base | 14.2 | 12.3 | 4.4 | 4.8 | 8.9 |
| Qwen3-1.7B Math (RL) | 35.6 | 31.7 | 19.6 | 15.2 | 25.5 |
| Qwen3-4B Base | 23.2 | 22.1 | 10.6 | 7.9 | 16.0 |
| Qwen3-4B Math (RL) | 58.8 | 55.8 | 33.1 | 38.3 | 46.5 |
| Qwen3-8B Base | 24.4 | 22.5 | 12.3 | 10.0 | 17.3 |
| **PUST (1.7B→8B)** | **54.4** | **40.2** | **22.1** | **31.3** | **37.2** |

分析：
- PUST 1.7B→8B 将 8B base 平均分从 17.3 提升至 37.2（+19.9），达到 4B 直接 RL（46.5）水平的约 80%。
- PUST 4B→8B 表现更好（平均分 47.5，λ=1.0），与 4B 直接 RL 水平持平。
- 代码域表现类似：PUST 在 HumanEval+、MBPP+ 和 LCB 上均稳定提升，其中 LCB 提升最为显著（+8.3）。

### 5.2 信号可复用性（Q2）

将同一代理模型（4B GRPO 500 步）提取的更新信号迁移到不同主模型（1.7B、4B、8B），均观察到了显著提升（论文 Table 3）。这验证了 PUST 的核心优势：探索信号与具体模型解耦，可从单一探索运行中批量服务多个下游主模型。

### 5.3 多轮传递的迁移性（Q3）

4B→1.7B→8B 链式迁移实验中（论文 Table 4），4B proxy 的更新信号先迁移至 1.7B 中间模型，再迁移至 8B 主模型。信号经过多轮传递后仍可维持良好的主模型性能（平均分 43.9，达到 4B 直接 RL 的 94.4%），这表明 PUST 信号具备良好的传递稳定性。

### 5.4 校准系数 $\lambda$ 的影响（Q4）

| $\lambda$ | AIME 24 | AIME 25 | 平均（8 项） |
|:---------:|:-------:|:-------:|:----------:|
| 0.5 | 57.29 | 41.88 | 30.85 |
| 0.75 | 61.25 | 50.63 | 44.14 |
| 0.95 | 60.83 | 50.21 | 44.46 |
| 1.0 | 62.50 | 52.71 | 44.92 |
| 1.1 | 63.54 | 52.92 | **45.17** |
| 1.5 | 60.42 | 48.33 | 38.74 |

关键发现（以 4B→8B 迁移为例）：
- $\lambda=0$ 导致完全崩溃（性能归零）—— 不设锚定校准会使主模型无限跟随静态代理信号，导致过更新。
- $\lambda=0.5$ 仍过于激进：验证精度早期达到峰值后退化。
- $\lambda \in [0.75, 1.1]$ 区域表现最佳且稳定。
- 代理-主模型差距越大（1.7B→8B），最优 $\lambda$ 越大（需要更强的校准约束）。

### 5.5 PUST vs 直接探索（Q5）

PUST 4B→4B 与 4B 直接 GRPO 对比：PUST 信号迁移与直接探索平均分持平（均为 46.5，100%），各子基准的比值在 97.9%~103.2% 之间。信号复用带来的主要优势在于：同一个 4B proxy 探索 500 步得到的信号可迁移到 1.7B/4B/8B 等多个下游模型，每个下游仅需 50 步训练即收敛，整体开销远小于每个模型分别进行 400~500 步直接探索。

## 第 6 章 代码实现与实用分析

### 6.1 仓库概览

项目代码将在论文发布两周后开源至 https://github.com/KnowledgeXLab/PUST。

实验模型权重已托管在 HuggingFace：
- https://huggingface.co/KnowledgeXLab/PUST-Experiments
- 包含：Qwen3-1.7B-Math-GRPO-Steps500、Qwen3-4B-Math-GRPO-Steps500、Qwen3-8B-Math-GRPO-Steps400 等

训练和评估代码基于以下开源项目构建：
- OpenRLHF、veRL（强化学习后训练框架）
- OpenCompass（评估框架）

### 6.2 实现要点

PUST 的实现相对简洁，核心由三个独立组件构成：

1. **Proxy Exploration**：标准 GRPO 训练，可复用现有的任何 RL 后训练代码。代理模型可在远小于主模型的规模上运行。
2. **Update-Signal Extraction**：前向两次推理（proxy base 和 proxy optimized），计算 token 级 log-ratio，存储为 $\Delta_{\phi}(a|s_t)$ 表。
3. **Signal Transfer**：在标准训练循环中，用预计算的 $\Delta_{\phi}$ 代替 reward 信号，引入 $\lambda$ 校准项形成新的 loss 函数。

关键超参数：校准系数 $\lambda$（推荐区间 0.75-1.1，随 proxy-primary 差距增大而增大）。

## 第 7 章 局限性与展望

### 7.1 局限性

1. **探索质量差距**：PUST 的信号迁移仍无法完全达到主模型直接探索的水平，存在 5-15% 的性能差距。代理模型可能探索到次优策略，约束了上限。
2. **最优 $\lambda$ 依赖于 proxy-primary 差距**：虽然总体趋势是 proxy 越弱 $\lambda$ 越大，但缺乏自动调优方法。
3. **当前仅在数学和代码域验证**：其他域（如对话对齐、安全 RLHF）尚未测试。
4. **静态信号问题**：$\Delta_{\phi}$ 提取后固定不变，主模型快速吸收后可能被有限的方向持续拉扯。$\lambda$ 校准是缓解手段，但非根本解决。

### 7.2 未来方向

- **自适应 $\lambda$ 调度**：训练过程中动态调整校准系数，初期激进、后期保守。
- **多代理并行探索**：同时部署多个 proxy 探索不同 reward 函数，生成多样化信号库供主模型选择。
- **非数学/代码域扩展**：通用对话、长上下文、工具使用等场景的验证。
- **在线信号更新**：主模型迁移过程中定期从代理模型重新抽取更新信号，缓解静态问题。
- **与 OPD 结合的层级架构**：PUST 负责上游探索信号生成，OPD 负责下游高效对齐，组合使用。
